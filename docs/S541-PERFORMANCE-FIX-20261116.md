# S541 控制条与构建耗时修正

> 历史记录（2026-11-16）：保留当时基线与阶段结果；当前行为、取舍和验证边界见 [性能说明](PERFORMANCE.md)，记录目录见 [历史索引](history/README.md)。

目标：小米手环 10 Pro / p67 / 固件 3.101.043，包含首页统计、快应用启动和模糊滑动修复。

## S541

旧控制条首次出现时，在 UI 线程连续两次打开 /dev/fb0，每次读取 24 行，
合计至少 48 次 lseek/read，再滤波、生成 110592 字节玻璃像素并清缓存。
移动时还会 invalidate 整个 336×480 透明附加层，扩大桌面/模糊的重绘范围。

本次：

- 不再从 S541 控制条路径读取 framebuffer，改为读取已发布、不可变的 V2 模糊背景。
  采样 API 不触发新截图、滤波、fence 或缓存修改，并检查源身份、格式、退休状态和边界。
- 控制条和点击区立即显示；坐标稳定至少 160ms 后才准备可选玻璃底色。
  没有缓存背景时仅省略玻璃底色，每 500ms 最多查询一次缓存，来源稍后出现仍可补上。
  这意味着关闭模糊时不再为 S541 单独截屏生成玻璃；按钮本身保持可见和可点击。
- 已经模糊的输入不再重复滤波。第一次写未发布的私有缓冲不需要 GPU fence，
  重用旧描述符时仍保留原安全 fence 和图像缓存清理。
- 仅失效旧控制条范围并通过原生 align 更新位置，不再 invalidate 全屏附加层。
- 原按钮 CLICKABLE 已经关闭时，不重复调用清标志 API。

控制条仍沿原来的维护周期跟随官方布局；本次没有改写原生输入或滚动算法，
也没有把它变成经过真机验证的 60fps 组件。玻璃视觉来自当前模糊背景，
会与旧版直接截取当前 framebuffer 的效果有所区别。

## 构建

此前即使只改 Rust 控制条，也重编全部 37 个网络 C 单元，重新生成图标、
构建 fetch/capatch。此前答复中的等待还包括源码定位、工具安装、回归和源码打包，
不能把整段对话耗时算成编译器耗时。

本次给网络对象增加内容缓存：校验源/头文件/网页资源、固件头、编译器身份、
参数与对象 SHA-256。文件或参数变化、对象损坏、CHAOS_NO_C_CACHE=1 时重新编译。
动态构建时间仅传给使用它的 net_glue.c，避免无关的 36 个单元每次失效。
保留精确对象列表与固件隔离，不用旧主模块替代新编译。

```powershell
python tools/build.py --firmware 10p-3.101.043 --no-icons --skip-fetch
```

上述命令复用经固件身份与哈希验证的 fetch/capatch 及现有图标，仍编译主模块、
链接并检查 ELF、打包并验证容器全部资源。修改相应资源或网络模块时需恢复完整构建。

本机测得网络冷缓存 7.93s、暖缓存 0.64s；本轮一次完整主模块到安装包约 20.22s。
最终产物的构建耗时另见交付目录 `test-logs/build-s541fix-time.txt`。

## 验证

- S541 5 项宿主测试，包括 120 帧移动期间零 framebuffer 读取、移动时不生成玻璃、
  全屏层不失效、缺失缓存时可见、缓存稍后到达、复用时 GPU 忙保护、像素/alpha。
- 实际生产缓存采样 API：边界、空/禁用/退休源、发布代数、坐标与颜色梯度校验。
- 网络构建缓存：命中、依赖/参数变化、对象损坏和强制重建。
- 首页统计、模糊交互、V2、构建流程回归，以及完整 ARM 编译和 ELF 检查。
