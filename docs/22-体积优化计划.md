# 22 · supervisor 模块体积优化计划

> 背景：`0adf20c` 合并官方 v1.0.8 后，`chaos_sup.ko` = **251,684 B**，贴着历史上沿用的 256 KB 红线；
> 应用管理重构（详情页 + 批量页 + 卸载）还要在这上面继续加代码。
> 本计划只做体积，不改功能行为。

## 1. 现状剖面

`supervisor/chaos_sup.ko`（251,684 B）各节：

| 节 | 大小 | 说明 |
|---|---:|---|
| `.bss` | 148,648 | NOBITS，不进文件、占运行内存；`page::LOG_VIEW` 48 KB、`appmgr::REG_BUF` 32 KB 是大头 |
| `.text` | 79,326 | 代码 |
| `.strtab` | 59,133 | 符号名。2,162 个符号里 **2,043 个是局部符号，名字占 56 KB**；全局/弱符号只有 119 个、2.6 KB |
| `.rodata` | 36,965 | 其中 **开源许可全文 ≈14.6 KB**（连续 72 列排版区，0x2D81–0x668A），`control_center` 图标路径拼接串 ≈5 KB |
| `.symtab` | 34,800 | 2,162 条；**重定位实际只引用 635 条**，其余是链接器保留、加载器用不到的 |
| `.rel.text` | 24,352 | 重定位（`R_ARM_ABS32` 等 4 类） |
| `.rel.rodata` | 5,800 | |
| `.ARM.exidx` + `.rel.ARM.exidx` | 10,064 | 展开表；`panic=abort` 下永远用不到 |
| `.data`/`.shstrtab`/其它 | <400 | |

结论：**文件体积的 37% 是符号名 + 符号表**，21% 是调试/许可类 rodata，只有 32% 是真正的代码。

## 2. 先把「256 KB 红线」验清楚

这条 256 KB 来自 `docs/07-Canopus.md` 的 `MODULE_MAX_SIZE`（Canopus 安装器的 Lua 检查），
**不是 modlib 的硬限制**；Chaos 自己的安装器（`installer/chaos_installer.lua`）并不查 ko 尺寸。
`docs/18` 里那句「insmod 上限」是当时的推断，没有真机证据。

实验（真机一次，10 分钟）：

1. 取当前可用的 251,684 B ko，尾部补 0 到 300 KB（ELF 解析按节表走，尾部垃圾不影响加载）；
2. `insmod /data/chaos/sup_test.ko chaos_sup_test`，看 `dmesg`；
3. 能加载 → 没有硬上限，体积优化按「延寿 + 省内存」推进，不必卡 256 KB；
   报错（如 `ENOMEM`/`EINVAL`/尺寸检查）→ 记录真实阈值，按阈值定目标。

> 无论结果如何，优化本身都值得做：ko 从 251 KB 降到 ~160 KB，装机快、`/data` 占用少、
> 后续详情页/批量页的预算就宽了。

## 3. 可用的手段（按风险从低到高）

### A. 构建参数（已实测，收益小）

| 手段 | 收益 | 风险 |
|---|---:|---|
| `-Cpanic=immediate-abort`（`-Zunstable-options`） | **-1,320 B**（实测 250,364） | 低：我们本来就 `panic=abort` |
| `-Zlocation-detail=none` | 0（实测无变化） | 低 |
| `--icf=all` | 用不了：`rust-lld -r` 不允许 ICF（实测报错） | — |

构建参数合计上限约 **1.3 KB**，只作为顺手项。

### B. 符号名瘦身（低风险，最大单笔收益）

加载器（NuttX modlib）做重定位只需要 `.symtab` 的**结构**和 index，不需要局部符号的名字；
`strtab` 只在「有未定义符号要解析」时才被查名——本模块未定义符号为 0。

做法：构建后处理，把 `STB_LOCAL` 且已定义的符号 `st_name` 置 0，
`GLOBAL/WEAK/未定义` 的名字保留（防止加载器导出符号表时用到）。

- 收益：**56,242 B** → 文件降到 **≈194 KB**
- 不改任何 offset/index，只改 `st_name` 和 `.strtab` 内容，实现最简单
- 风险：低。真机验证：`insmod` + 进页 1/设置页 + 触发一次 `chaos_shake_timer`

### C. 符号表裁剪（中风险，再省 24 KB）

`.symtab` 2,162 条里只有 635 条被重定位引用。保留：

1. 重定位引用到的符号；
2. `STB_GLOBAL`/`STB_WEAK` 且已定义的符号（119 条，导出用）；
3. `STT_SECTION` 段符号；
4. 未定义符号（本模块为 0）。

删掉其余 1,500+ 条，并**同步重写所有 `.rel.*` 里的 `r_sym` 下标**。

- 收益：`(2162−638)×16 ≈ 24,400 B`，叠加 B 后文件 **≈160 KB**（原型已跑通：`157,312 B`，含全空名字）
- 风险：中。modlib 若有「遍历全符号表做二次解析」的路径会受影响；
  用「保留全部全局符号 + 真机冒烟」兜底，失败就退到只做 B

### D. 删展开表（低-中风险，10 KB）

`.ARM.exidx` / `.rel.ARM.exidx`（各 5,032 B）在 `panic=abort` 下没有消费者。
把两节 `sh_size=0`（保留节表项，避免 index 变化），重排后即省 10 KB。

- 风险：若有 C++ 异常/C 的 `_Unwind` 路径会缺表；本模块纯 Rust + abort，理论安全
- 与 B/C 同一个后处理脚本里做，真机一并验

### E. rodata 内容（需要拍板，~14 KB）

开源许可全文 14.6 KB 直嵌在 `.rodata`（关于页「开源许可」展示 MPL 2.0 等）。
可选：

1. 只保留许可名称 + 版本 + 仓库内链接（合规上通常要求“随分发提供许可文本”，放到 README/docs 即可满足分发，模组内不必全量展示）；
2. 截断为前 N 行 + 「完整文本见项目仓库」；
3. 保持现状（不动）。

这一步影响合规表述，**等用户拍板再做**，不默认执行。

### F. 图标路径表去重（~5 KB）

`/resource/app/control_center/icon/...` 一串路径是「前缀 + 控件名」硬拼接。
改为前缀常量 + 控件名表（名字都在），运行时 `memcpy` 拼，省掉重复的 `/resource/app/control_center/icon/` 前缀。

### G. 内存侧（不影响文件，仅当 `.bss` 也算限制时做）

- `LOG_VIEW` 48 KB → 环形 8–16 KB（日志页只显示最近若干行）；
- `REG_BUF` 32 KB → 按实际 apps.json 大小动态分块（现在是一次性静态缓冲）；
- `SW_BAK` 6.2 KB、`ICON_FILES` 4.8 KB 等待核实必要性。

若第 2 节实验证明「上限与内存无关」，G 只作为省 RAM 的可选项。

## 4. 分阶段计划

| 阶段 | 内容 | 预期 ko | 验收 |
|---|---|---:|---|
| S0 | 真机补零实验，确认 256 KB 是否真实 | — | 记录 `dmesg` 结论 |
| S1 | B（局部符号名置空），新增 `tools/ko_slim.js` 接进 `build_ko.sh` | ≈194 KB | 本地 `verify_chaos_ko` 通过 + 真机 insmod/页面冒烟 |
| S2 | C + D（裁符号表 + 删 exidx），重写 reloc r_sym | ≈160 KB | 同上；连做两次开关机 + 隐藏/显示一轮 |
| S3 | F（路径表去重），顺带 A（immediate-abort） | ≈154 KB | 同上 |
| S4 | E（许可文本）——等用户决定 | ≈140 KB | 关于页许可入口可正常打开 |
| S5 | 可选 G（LOG_VIEW/REG_BUF 收缩） | 文件不变 | 日志页、应用列表功能回归 |

S1 和 S2 分开验证：S1 出问题只回退「名字置空」，S2 出问题回退「符号裁剪」，互不牵连。
每个阶段的 ko 都留在 `supervisor/` 下命名保存（`chaos_sup.s1.ko` 等），回滚就是刷回上一个。

## 5. 验证清单

本地（每阶段）：

- `node tools/verify_chaos_ko.js`：未定义符号 0、`.text`/`.init_array` 非 0、e_entry 预期；
- 节表检查：`.text` 大小与基线偏差 <5%，`.rel.text` 条目数不变（S2 只改 r_sym 不改条数）；
- 反汇编抽查：`0xC54A561/0xC54A819/0xC549679` 三条调用点仍在（可在 `.text` 里按字节特征搜）。

真机（S1、S2 各一次）：

- `insmod` 成功，`dmesg` 无 fault；
- 页 1 应用管理能列出应用；隐藏一个 → 图标消失；显示 → 回来；
- 设置 → 关于页能进（覆盖大部分页面注册与 UI 代码）；
- 触发一次换绑/重同步路径（或点「重新应用隐藏」）不崩。

失败回滚：`git revert` 掉 `tools/ko_slim.js` 与 `build_ko.sh` 的接入，刷回保存的上一版 ko。

## 6. 风险与开放问题

1. **modlib 对符号表的真实依赖未验证**：需要真机 S1/S2 冒烟；若 S1 就崩，说明加载器读局部符号名，整个 B 方案作废，改走 E/F/G。
2. **256 KB 是否真实**：S0 实验回答；文档 07 的来源是 Canopus 安装器，不是 modlib。
3. **许可文本**：E 需要用户确认合规口径。
4. **`.bss` 148 KB**：若实测内存吃紧，S5 再做；不影响文件体积红线。
