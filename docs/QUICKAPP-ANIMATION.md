# 快应用动画（10 Pro试验适配）

主页“工具”分组中的“快应用动画”为设置入口，位于“系统美化”下方。进入后显示“快应用开启动画”和“快应用关闭动画”两个独立开关，默认关闭，分别保存在`/data/chaos/quickapp-animation.cfg`与`/data/chaos/quickapp-close-animation.cfg`。界面使用功能名称，不显示参考项目名称。页面注册号46，沿用既有开启配置，新增关闭开关不会重置原设置。

参考用户提供的`~/Downloads/Vela_NativeApp-syspatch 4/ELF/src/syspatch_qa_anim_page.c`的启动入口、创建/前台回调与原生动画调用逻辑，重新核对p67/3.101.043，不复制其他机型的地址、页码或线程机制。当前为Rust适配，已加入点击时的原生图标启动遮罩和退出过渡；暂不拆分固件引擎线程等待。

## 固件证据

- launcher点击`0x0C517418`创建0x38字节上下文（初始化`0x0CA45609`）；动画类型`ctx+8=0x33`，图标中心写入`ctx+0x24/+0x28`，与参考机型的0x30字节和+0x1C/+0x20不同。
- 请求描述符入口为`0x0CA46249`，读取上下文后调用原生动画驱动`0x0CA45C6C`。只传入根对象、空完成回调及初始化后的上下文。
- 原生show_app入口`0x0CA6CC99`。原生请求函数`0x0CA6D4B5`在`0x0CA6D518..52A`从接口`0x200EB684+4`读取vtable指针，再读取vtable+0x18并调用。原表在`0x2CDE7D18`，共15个方法；启动入口为第6项。安装时逐项核验原表，复制到模块常驻RAM，仅改第6项，再把`0x200EB688`改为副本指针；原只读表不写入，其他方法完整保留。第三方已改动的方法表不覆盖。
- show_app的fallback在`0x0CA6CD68..70`读取`[0x200EB640+0x18]`的vtable+0x4C方法查找运行态应用。注册节点与运行态记录不同，查找后再核对`record+0x16`应用ID。
- QuickApp构造函数`0x0C5478D1`原始指令将创建`0x0C547699`、前台`0x0C547765`、隐藏`0x0C5475F9`、销毁`0x0C54751D`分别写入`record+0x4C/+0x50/+0x5C/+0x64`。原前台回调读取`record+4`代理；原创建回调将336×480根对象写入`proxy+0x2C`。`proxy+0x39`是已显示标记，原隐藏回调检查并清除此标记，销毁回调也在删除根对象前处理它。

## 行为与限制

show wrapper保留原始调用及返回值，仅对ID大于255、创建入口精确匹配的快应用替换创建/前台回调；关闭动画开启时再挂接隐藏/销毁回调。上下文同步复制，不持有launcher栈指针。原创建/前台回调执行后重新按ID查询，避免使用回调内销毁的旧记录。UI维护等待应用真正前台、根对象存在且非隐藏，再调用固件打开动画一次；普通前台等待最长20拍后放弃，失败时正常启动仍由系统处理。动画等待期间使用现有快维护节拍，不新增线程。

两个开关均关闭时恢复自己持有的接口vtable指针，并沿当前注册链重新查询记录，只恢复仍为自有wrapper的四个回调，不覆盖第三方hook。单独关闭某项立即取消该项过渡；另一个开关可继续工作。模块驻留与其他功能相同，不支持在仍有回调时直接卸载代码。

`tools/probe_quickapp_animation.py`执行精确固件的实际启动请求函数、QuickApp构造与原生动画参数构建，生产Rust适配编译为ARM后在Unicorn运行；应用引擎、注册查找、底层动画驱动及配置IO使用显式替身。覆盖真实间接启动调用、普通应用不修改、创建/前台原调用保留、可见性等待、只播一次、方法表其余14项不变、原Flash表不变、旧错误地址不写入、第三方hook拒绝及关闭恢复。该验证不证明冷启动阻塞之后第一帧已绘制，也不证明动画已经在真机显示。

## 入口未匹配修正

首版误将`0x200EB6E0+0x18`当作show_app内联槽，实际该接口属于另一组启动请求服务；真正的show_app通过`[0x200EB684+4]+0x18`调用。旧探针直接将期望函数写进错误地址再触发wrapper，无法发现间接层缺失。修正版以固件真实Flash表为输入，并执行原生请求函数证明CPU通过副本第6项进入wrapper。状态仅在实际接口仍指向模块副本时显示“已开启”。

真机需分别测试已运行快应用再次打开和冷启动、连续打开、返回后重新进入及开关关闭恢复。此版本先完成动画再串行调用原生引擎，未实现并行引擎加载，不应宣称冷启动耗时缩短或UI加载期间完全不阻塞。

## 点击后先动画，再加载

旧实现只在创建/前台回调返回后播放根对象动画，无法覆盖冷启动的同步等待。新增`quickapp_splash.rs`在顶层创建不透明全屏底色和应用图标，使用同一个原生打开动画入口，200ms过渡，从launcher上下文保留图标中心。普通桌面空参数启动先持有ID和自有0x38字节动画描述符副本，不持有原请求栈；至少240ms且收到遮罩DRAW_MAIN后，下一UI维护回调只调用原show_app一次。非空启动参数、未知动画描述符和无法创建遮罩的情况保留原始同步调用。

顶层getter经miwear属性表定位为`0x0CAC0219`，真实函数读取display+0x2C8。遮罩留在系统顶层覆盖引擎的空白阶段；待目标根对象可见、出现内容子对象并经过两次维护后，180ms淡出，同时让底层重画。该就绪判据基于对象内容，未接入参考实现的JS Page确认，因此真机仍需检查首屏慢渲染场景。启动前息屏或离开桌面会取消；首帧通知2秒缺失时正常启动回退；加载超过10秒会释放遮罩。

前台判断兼容共享代理原生页：除动态app_id相等外，也核对快应用根对象是否属于当前页根。不能仅凭top_app_id与动态ID不等就丢掉动画。生产ARM探针模拟代理页ID0x29承载动态ID0x123，验证动画先于引擎提交、无首帧时不提前提交、请求仅一次、遮罩跨加载保留、内容门控后淡出、未知参数同步传递及无首帧超时回退。

## 关闭时保留画面，返回桌面播放原生过渡

`quickapp_exit.rs`在调用原隐藏/销毁回调前捕获根对象画面，仅处理`proxy+0x39`非零、根对象未隐藏的快应用；要求该根对象属于当前前台页，或系统已先切回桌面。后台实例销毁和同一次HIDE→DESTROY不重复捕获。原回调始终照常执行，之后不再访问原根对象。

快照使用固件分配器`0x0C587F39(336,480,15,0)`和截图入口`0x0CAC0879(root,15,descriptor)`，格式15为BGR888，像素约占473KiB。分配前与截图后检查既有GPU/native-layer空闲保护。成功捕获后，在原HIDE/DESTROY之前立即建立全屏顶层遮罩，保持退出前的画面；原回调返回时立即检查是否已返回桌面并启动OUT，不等待下一次维护。桌面尚未就绪时保持遮罩，等待最长1500ms；切换到其他应用时立即取消。分配失败、截图失败或GPU忙时保留系统退出流程，不再插入内容不同的黑底图标回退。

调用`0x0CA462D9(cover,completed,ctx)`，上下文由`0x0CA45609`初始化为14个word，保留打开时的图标中心（+0x24/+0x28），duration=200ms、delay=0。真实OUT构建器`0x0CA45DB0`接收alpha 255→0、scale 256→204，与固件原生关闭配方一致。该构建器经`0x0CA45508`建立自己的过渡图像，再隐藏源cover；源cover在OUT结束后继续隐藏，不能主动重新显示。完成函数`0x0CA45C21`共用16字节数据中的计数（+8=2、+12=已完成数），两个分量均完成后先经`0x0CA455E4`删除原生过渡图像，再以`lv_anim_t*`调用completed。模块仅核对`animation+0`为本次cover后登记完成，下一UI维护删除隐藏的源cover；不在原生完成回调中销毁对象。不再根据DRAW_MAIN与240ms估计动画完成；原生完成回调缺失时1500ms兜底。息屏、开关关闭或切换到其他应用时取消。

删除遮罩后，快照先进入两个槽位的退役队列；后续维护确认GPU/native-layer空闲后，再通过`fw_img_free_by_path`清理图像缓存，调用`0x0CAC0DB9`释放。没有退役空位时不分配新快照。息屏时不为待回收资源强制维持快维护节拍。

生产ARM探针额外验证仅开启关闭动画不会播放IN、完整画面遮罩先于原HIDE/DESTROY、连续隐藏/销毁只捕获一次、返回桌面同回调启动OUT、真实OUT参数、GPU忙时不插入异样画面、跳转其他应用取消，以及遮罩删除后等待GPU空闲才清缓存和释放。执行真实`0x0CA45C21`两次，验证首次分量结束不删除源cover，两个分量完成并移除过渡图像后才允许模块回收源cover；超过240ms但没有完成通知时也不会过早删除。截图、LVGL对象与底层动画驱动仍使用显式替身，实际画面、退出路径和性能需要真机验证。

首版的闪屏交接缺陷：原回调已退出，模块仍等维护定时器（空闲亮屏200ms）再创建退出遮罩，可能先露出桌面再恢复快应用画面。改为关闭前建立遮罩、原回调返回后交接，并移除可能造成画面突变的图标回退。完成时机同时改用固件的双分量完成通知，避免维护拍猜测动画生命周期。
