# 应用图标选择

入口：Chaos → 设置 → **应用图标**。三级列表只保留两项，全部输出为 **96×96**：

| 选项 | 来源 | 显示方式 |
|---|---|---|
| 原版 | `tools/chaos.png` | 静态，复用安装器部署的 `/data/chaos/chaos_icon.bin` |
| 动态 | `tools/chaos.gif`，用户新上传 GIF | 193 帧、5.2 秒无限循环，默认选中 |

首次安装及从旧五项列表/开关版本升级，自动选择动态。之后手动改选原版或动态，选择会在重启后保留。
更新安装包后需重启加载新模块。单选页仍为第 43 页，页面总数为 44；设置入口显示当前选择的副标题。

## 资源与体积

构建时处理 GIF 的透明度、局部帧与 disposal，将原始 320×320 的 193 帧统一缩放为 96×96，
保留 20–740 ms 的各帧时长和 5.2 秒循环。共用 256 色 RGBA 调色板，以原生索引透明格式
（cf `0x0A`）和 PackBits 保存到 `supervisor/assets/dynamic-icon.frames`，压缩资源约 558 KiB。
不额外增加旋转、缩放或抽帧，不需要手环运行 GIF 解码器。

移除其他主题源图、旧 GIF、独立 SVG 暂停图和四份内嵌静态资源。原版、暂停与切回静态直接使用
已有的原版文件，无需在模块中重复保存静态像素，也不再分配两份 BGRA 静态缓冲。
仅保留两份 10 KiB 播放缓冲（调色板 + 96×96 索引），对齐、描述符及原生解码缓存另计。
安装包的桌面和设置入口原版图标仍为 96×96，PNG 以 4 倍超采样处理透明外沿。

## 设置与播放

配置使用 `/data/chaos/app-icon.cfg`，5 字节 `AIC2` + 选项 ID（0=原版、1=动态）。
旧 `AIC1`、旧开关配置或没有有效配置时，按用户要求自动选动态并保存新记录；不会把旧主题 ID
误当成本版选项。写入使用临时文件、关闭与回读核对后 rename，失败至少间隔 1 秒重试。
点击回调只更新内存并排队，磁盘与图像更新都由 UI owner 定时器处理。

动画按单调时钟选帧，活动节拍 20 ms；发生延迟时直接显示当前应有的帧，避免累积变慢。
定时器只创建一次，与系统美化图标包共用。自身暂停/选择原版时撤销自身请求，所有播放源都暂停后才降到 1000 ms；现有 50 ms 维护节拍保持。
息屏/AOD 不扫描或重画图标。离开桌面、移出屏幕、长按/原生排序编辑和快照转场时暂停并恢复原版，
再次可见或亮屏后从 GIF 第一帧开始。原版静态模式不持续换图或复制像素。

每次从当前 launcher 子对象表重新找到 Chaos 的 app_id，保留原生点击、位置和缩放。
图源被其他模块替换时默认保留，明确重新选择可应用本模块图标。升级时的自动动态选择也会排队应用。

播放交替更新非当前缓冲，回收其旧缓存后解码，再切换原生图源并回收上一帧缓存。
恢复原版文件时，原生 setter 会复制路径，内存分配失败可能不切换图源；因此必须由下一次
存活对象查找确认原版已绑定，再回收两份播放缓存。失败保持待处理并重试，不能提前回收当前帧。
原生 setter 可能派发 DELETE，返回后不再读取实例。描述符与播放像素在模块生命周期内保持有效。

## 构建与验证

```sh
python3 tools/build.py
python3 tools/build_gif_icon.py --check
python3 tools/test_gif_icon.py
python3 tools/test_static_icon.py
python3 tools/test_dynamic_icon.py
python3 tools/verify_dynamic_icon_abi.py /path/to/vela_ap.bin --probe
```

主机回归覆盖默认动态、旧配置升级、两项选择保存与重启、193 帧像素/时序/透明角、损坏资源、
快速切换、暂停/唤醒、桌面重建、文件恢复失败重试及缓存确认顺序。
ARM 探针运行生产图像端口和精确固件原生 setter，核验 96×96 像素、原版文件恢复/继续播放、
路径复制与释放、OOM 保留旧图源、双缓冲 64 字节对齐、定时器节拍和 DELETE 后无实例读取。

固件只支持 p67 / **3.101.043**。探针的文件头解码注册、堆分配和 GPU 缓存使用主机模型，
实际流畅度、触摸、功耗与低内存表现仍需真机验收。
