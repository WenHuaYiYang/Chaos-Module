# 模糊V2：SysPatch IIR第一阶段移植

当前界面只保留“模糊v2”，使用SysPatch四方向12位定点IIR滤波，radius=12。V2只读取自身blur_v2.cfg，旧Corona配置不参与启用判断，也不能选择旧滤波算法。系统背景关闭V2。四区适配仍含Corona派生代码，相关许可与来源集中在“开放源代码许可”页保留；此状态不代表源码已完全独立或净室实现。

原始来源为用户提供的`~/Downloads/Vela_NativeApp-syspatch 4/ELF/src/syspatch_blur.c`和同名头文件，原样保存在`supervisor/syspatch_blur/`。文件头记载其来源为LVGL软件模糊，保留全部上游注释和相邻LVGL 9.5许可文本；该许可文本不代表为整个SysPatch项目重新指定许可。

第一阶段只移植纯像素滤波：输入为已核对的3.101.043表盘快照，经4×面积降采样得到84×120 BGR888，运行SysPatch每通道8位分支并应用70%暗化，再按像素中心双线性插值生成336×480 BGR888，以1×比例绘制。并未移植其他机型的466×466结构、硬编码地址或七级GPU高斯管线，也尚未接入其GPU缩小/软件滤波/GPU放大的完整后台。

四区区域选择、绘制/滚动/DELETE hook、GPU fence、快照所有权、缓存退役及通知图标透明处理仍复用当前p67适配。切换算法仅在原生idle门通过后执行，作废旧滤波结果并重新请求采集；仅在原生provider和draw适配中加入受CHAOS_BLUR_V2_COLOR控制的颜色扩展，未开启扩展的原Corona行为保持原样；原始上游摘要在测试ADAPTED清单保留。诊断`algorithm=0`为Corona，`algorithm=1`为SysPatch IIR。

因此当前V2不是独立于Corona的完整实现，不能删除Corona代码、AGPL许可及界面署名。后续需要逐项替换四区生命周期及快照/发布适配，并在真机核对效果、帧耗时和低内存表现，再做最终清理。

主机测试`supervisor/tests/syspatch_filter_test.c`验证Corona分支逐像素不变、V2与原始SysPatch三通道调用逐像素一致、两算法输出不同、白图不变黑和边界拒绝。完整构建仅证明目标ABI链接，不代表真机验收。

运行`python3 tools/test_blur_v2.py`验证源码摘要、滤波和生产选择器；`python3 tools/test_corona_blur.py`验证原有四区和19项配置回归。真机进入系统模糊，分别选择Corona与V2，对照四区效果及进出活力指标后的恢复，再决定下一阶段适配。

## 2026-11-15 细腻度与灰白偏绿修正

旧V2对RGB565的5/6/5位通道反复滤波、截断暗化，随后直接放大84×120图，存在色阶误差与块状感。新V2从336×480 BGR888快照直接平均到8位颜色缓冲，避免先转565；IIR保持上游原代码、使用3字节分支，暗化统一舍入，发布全分辨率BGR888。输出按源描述符尺寸选择1×绘制，切换期间旧565源仍沿用4×路径。

V2使用PRECISION和skip=1，每一行、每一列均参与滤波，取消默认AUTO在radius=12时的隔行/隔列复制填充。

双输出使用原生绘图分配器、相同GPU fence/cache与退役逻辑。每张像素图从约20 KB增加至约484 KB（stride对齐时略大），最多两张；双线性放大仅在背景生成时执行，不在每个滚动帧执行。内存和生成耗时需真机评估。主机回归覆盖白/灰色中性、8位快照绕过565、平滑渐变、边缘钳制及stride padding不被改写。
