# 模糊V2：SysPatch IIR第一阶段移植

当前界面只保留“模糊v2”，使用SysPatch四方向12位定点IIR滤波，radius=12。V2只读取自身blur_v2.cfg，旧Corona配置不参与启用判断，也不能选择旧滤波算法。系统背景关闭V2。四区适配仍含Corona派生代码，相关许可与来源集中在“开放源代码许可”页保留；此状态不代表源码已完全独立或净室实现。

原始来源为用户提供的`~/Downloads/Vela_NativeApp-syspatch 4/ELF/src/syspatch_blur.c`和同名头文件，原样保存在`supervisor/syspatch_blur/`。文件头记载其来源为LVGL软件模糊，保留全部上游注释和相邻LVGL 9.5许可文本；该许可文本不代表为整个SysPatch项目重新指定许可。

第一阶段只移植纯像素滤波：输入为已核对的3.101.043表盘快照，经4×面积降采样得到84×120 BGR888，运行SysPatch每通道8位分支并应用70%暗化，再按像素中心双线性插值生成336×480 BGR888，以1×比例绘制。并未移植其他机型的466×466结构、硬编码地址或七级GPU高斯管线，也尚未接入其GPU缩小/软件滤波/GPU放大的完整后台。

四区区域选择、绘制/滚动/DELETE hook、GPU fence、快照所有权、缓存退役及通知图标透明处理仍复用当前p67适配。切换算法仅在原生idle门通过后执行，作废旧滤波结果并重新请求采集；仅在原生provider和draw适配中加入受CHAOS_BLUR_V2_COLOR控制的颜色扩展，未开启扩展的原Corona行为保持原样；原始上游摘要在测试ADAPTED清单保留。诊断`algorithm=0`为Corona，`algorithm=1`为SysPatch IIR。

因此当前V2不是独立于Corona的完整实现，不能删除Corona代码、AGPL许可及界面署名。后续需要逐项替换四区生命周期及快照/发布适配，并在真机核对效果、帧耗时和低内存表现，再做最终清理。

主机测试`supervisor/tests/syspatch_filter_test.c`验证Corona分支逐像素不变、V2与原始SysPatch三通道调用逐像素一致、两算法输出不同、白图不变黑和边界拒绝。完整构建仅证明目标ABI链接，不代表真机验收。

运行`python3 tools/test_blur_v2.py`验证源码摘要、滤波和生产选择器；`python3 tools/test_corona_blur.py`验证原有四区和19项配置回归。真机进入系统模糊，分别选择Corona与V2，对照四区效果及进出活力指标后的恢复，再决定下一阶段适配。

## 2026-11-15 细腻度与灰白偏绿修正

旧V2对RGB565的5/6/5位通道反复滤波、截断暗化，随后直接放大84×120图，存在色阶误差与块状感。新V2从336×480 BGR888快照直接平均到8位颜色缓冲，避免先转565；IIR保持上游原代码、使用3字节分支，暗化统一舍入，发布全分辨率BGR888。输出按源描述符尺寸选择1×绘制，切换期间旧565源仍沿用4×路径。

V2使用PRECISION和skip=1，每一行、每一列均参与滤波，取消默认AUTO在radius=12时的隔行/隔列复制填充。

双输出使用原生绘图分配器、相同GPU fence/cache与退役逻辑。每张像素图从约20 KB增加至约484 KB（stride对齐时略大），最多两张；双线性放大仅在背景生成时执行，不在每个滚动帧执行。内存和生成耗时需真机评估。主机回归覆盖白/灰色中性、8位快照绕过565、平滑渐变、边缘钳制及stride padding不被改写。

## 2026-11-15 实时按钮与自定义参数

“系统美化 → 模糊V2参数”提供“背景调整”和“按钮调整”。每边按
“模糊与透明度 / 色彩调整 / 刷新与重置”分组，均用纯数字键盘输入、自动保存。
共有 21 项参数，背景 10 项，按钮 11 项（含 RGB 三个独立值）：

| 参数 | 范围 | 背景默认 | 按钮默认 |
| --- | --- | --- | --- |
| 模糊强度 | 0..40 | 12 | 12 |
| 亮度 | 0..200% | 70% | 31% |
| 背景 / 玻璃不透明度 | 0..100% | 100% | 75% |
| 状态底色不透明度 | 0..100% | — | 38% |
| 饱和度 | 0..200% | 100% | 75% |
| 对比度 | 0..200% | 100% | 100% |
| 染色比例 | 0..100% | 0% | 0% |
| 染色红 / 绿 / 蓝 | 各 0..255 | 0 / 0 / 0 | 0 / 0 / 0 |
| 背景采集间隔 | 100..5000 ms | 500 ms | 500 ms |

强度 0 完全跳过滤波，保留原始快照；亮度 100% 为原亮度，超过 100% 可提亮。
饱和度 0 为灰度、100% 为原色、超过 100% 增强色彩；对比度围绕 128 调整，
0% 先变为均匀灰色，再受亮度及染色影响。
染色比例 0 不染色、100% 完全覆盖为所设 RGB，支持纯色、灰度和强烈色彩风格。
整数运算按通道钳制而非溢出回绕。颜色顺序：饱和度 → 对比度 → 亮度 → RGB 混合。
按钮默认饱和度 75% 保留旧版的适量去饱和效果。

背景不透明度直接控制四区共用的 GPU 图像任务 opacity；0 隐藏这一模糊层、
透出当前下层画面，不保证下层一定在绘制表盘。按钮玻璃和原生状态底色是两层，
若要完全透明，两项不透明度均需设为 0。图标与官方状态行为保留。

每组可单独恢复默认，不更改另一组。关闭 V2 时也可保存。
两组共用原始表盘采集及发布时机，各自的可见区域按各自间隔请求采集，
可见区域中更短的间隔可能让两组的共享源都更快更新。
背景自动刷新仅在已确认进入、开启对应区域、亮屏时请求，挂起采集不会反复作废；
按钮仍需可见且亮屏。所有采集保留原 provider 的安全 START/所有权检查。
按钮位置取样随显示帧更新，不受采集间隔限频。

配置仍在 `/data/chaos/blur_v2_params.cfg`，新格式为 47 字节：`BVP3` magic，
21 个 u16LE，最后一字节为前 46 字节以 0xa5 为种子的 XOR。
具体索引、范围和默认值对应 `supervisor/blur_v2_params.h` 与 Rust 配置模块。
缺失、截断、校验或范围错误回到默认。

兼容旧 17 字节 `BVP1` 和 19 字节 `BVP2`，读取时先按各自旧范围校验；
`BVP1` 将旧 radius 复制为按钮 radius，按钮亮度转换为
`round(旧背景亮度 × 旧按钮亮度 / 100)`，尽量保留原明暗。
`BVP2` 保留独立强度及亮度。两种旧格式的采集间隔初始化为两组相同值，
新增色彩参数采用保持原观感的默认值；下一次保存写入 `BVP3`。
读写处理短操作，写入或 close 失败保留错误状态，同值再次保存也可重试。
这是校验格式，不承诺断电原子写入；坏配置拒绝并回退默认。

UI-owner 在 native idle 时应用，忙碌保留 dirty 并在后续 tick 重试。
背景强度、亮度、色彩变化或按钮强度变化请求重新生成源；
按钮调色只重建 atlas，透明度在绘制层生效，不逐帧调色或滤波。
表盘降采样后从原始 84×120 BGR888 分别滤波，两个 radius 相同时复用暗化前结果。
每个原生输出槽配对保存一份按钮源，只读取当前已发布、未退休的槽；
失败或未发布的下一代不会污染当前按钮。
相比最初共用背景图的版本，独立模糊新增静态内存 90,720 字节，
包括 30,240 字节工作区与双输出配套的 60,480 字节。增加这些色彩选项不再新增整屏缓冲。

按钮 atlas、预制圆角、START 实时取样和 GPU 缩放/混合路径见
[控制中心按钮模糊](CONTROL-CENTER-BUTTON-BLUR.md)。

验证：`tools/test_blur_params.py` 覆盖两代迁移、两组独立重置、范围、保存及 busy 延迟；
`tools/test_blur_v2.py` 验证两路滤波独立、零模糊、灰度/对比度/强染色/提亮钳制、
GPU 背景透明度端点、独立刷新限频/可见性/熄屏/计时回绕、发布槽配对与退休拒绝；
`tools/test_cc_buttons.py` 覆盖实际按钮调色、atlas、连续 120 帧拖动、
无额外逐帧分配/圆角计算及批量同步。
另保留 Corona 全量回归、键盘 35 项回归和完整 3.101.043 构建。
以上均为主机/构建验证，实际显示与 FPS 仍需真机验收。

## 2026-11-15 列表震动与 V2 并存

旧列表震动依赖 legacy 背景流程的 `watch_structure()` 注册回调；
V2 的 `corona_tick()` 提前接管并返回，导致先开 V2 再开列表震动时监听没有装上。
现在由背景引擎选择之前的独立 `sv_watch_tick()` 维护原生 launcher 监听。
只校验 launcher，其他面板尚未创建不阻塞它；每拍复核事件记录，DELETE、
对象重建或系统清空订阅后可重新绑定。关闭开关后回调不再排入震动。

回调保留输入事件与磁贴增删冒泡触发，忽略绘制/样式刷新，
避免 V2 静止刷新时持续震动。震动仍延后到 UI tick，保留 100ms 冷却与系统震动设置。
`python3 tools/test_swipe_vibration.py` 验证订阅顺序、去重、失败重试、
删除/重建、开关、冒泡、静止绘制不震、冷却与计数回绕，以及原有返回/测试震动。
实机滑动震感仍需验收。
