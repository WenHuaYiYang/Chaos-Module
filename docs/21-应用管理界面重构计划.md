# 21 应用管理界面重构计划（统一隐藏 / 列表+批量+详情 / 卸载）

> 状态：计划稿 v3（按 m01357、m01394 调整），待确认后施工。
> 关联：`docs/08-Chaos.md`、`docs/14-应用隐藏与免重启模式.md`、`docs/19-快应用启动链路.md`。

## 1. 目标（对齐 m01230 + m01357 + m01394）

1. **应用管理列表**：每行应用名 + 下方小字状态（是否隐藏），状态用醒目颜色；点击整行进**详情页**。
2. **批量操作页**：应用管理最上面「批量操作」入口；可**全选/取消全选**，对选中的应用执行**隐藏 / 显示 / 删除**。
3. **详情页**：**图标 + 应用名（小字包名）+ 应用大小 + 版本号**；下面是显示/隐藏、排除/取消排除、卸载（二次确认）按钮。
4. **应用大小是动态值**：每次进详情页重新计算（升级/覆盖安装后大小会变），不长期缓存。
5. **卸载按 SmartHome 原理**（`smash.lua` 系统工具表盘的做法）：删 `apps.json` / `apps.json_hide` 条目 + 递归删应用目录，绕开 Vela 应用管理框架；但**要求立即生效**——删完顺手摘桌面图标并 `reload()`，不让用户等重启。
6. **排除项管理**：与应用管理同构，详情页同样有卸载按钮。
7. **取消普通/深度两种模式**：统一“深度隐藏”原理（条目移出 `apps.json`），靠本地重同步/重建节点显示，不再要求重启。
8. **列表只含快应用注册表条目**：系统应用本来就不在其中，不做“系统应用不可删除”的专门分支；仅用固件的“不可卸载”标志（节点描述符 `+0x12` bit2）兜底。

## 3. 统一隐藏模型

### 3.1 新语义

```
隐藏 := 条目在 apps.json_hide（hideFlag:true）
显示 := 条目在 apps.json
```

节点隐藏位、桌面图标都是派生态，不是真相来源。

### 3.2 操作流程

**隐藏**：`move_vis_to_hide(pkg)` → 节点在册则 `set_node_hidden(true)` + `app_launcher_del(id)` → `reload()`。

**显示**：`quickapp_resync_missing()`（节点不在册先重建）→ `move_hide_to_vis(pkg)` → `set_node_hidden(false)` + `app_launcher_del` + `app_launcher_add` → `reload()`。

**开机**：条目不在 `apps.json` → 不注册、无图标；手机重同步把节点建回来时由看门狗补隐藏。

**手机重同步**：`watch_keep()` 检测 `reg_sig_rt()` 变化 → 对隐藏名单逐条 `set_node_hidden(true)` + `app_launcher_del(id)`。

### 3.3 迁移

- 旧 `APPLY_MODE==1` 且 keep 名单非空：逐条 `move_vis_to_hide`，失败回滚；
- `APPLY_MODE==0`：无需动作；
- 成功后删 `chaos_appmgr_mode.cfg`、`appmgr_keep.bin`，写迁移标记；
- 迁移期间只读。

### 3.4 删除/停用旧机制

`APPLY_MODE`、`cfg_mode_*`、`deep_on()`、`toggle_apply_mode()`、`do_mode_apply()`、`keep_*`（读函数留到迁移完）、页1 深度开关行、“重启后生效”提示。

### 3.5 收益与风险

- 收益：即时生效、换绑不重现、显示免重启、状态单一。
- 风险：改写 `apps.json`，写前备份 `apps.json.bak`，写后校验再删；失败回滚。

## 6. 应用大小（动态）

- 路径 `/data/app/quickapp/<pkg>/`；递归 `opendir → readdir`（`d_type` 判目录/文件），文件 `open` + `lseek(fd,0,SEEK_END)`；
- **每次进详情页现算**（升级/覆盖安装后大小会变，不缓存跨会话）；算完前显示“计算中…”；
- 限深度 8、文件数 2000，防死循环；
- <1 MB 显示 `xxx kB`，否则 `x.x MB`；目录不存在显示 `—`。

## 7. 卸载（SmartHome 原理：改注册表 + 文件级删除）

用户提供的实际实现（`smash.lua`，系统工具表盘）是**绕开 Vela 应用管理框架**：`os.execute` 跑 shell `rm -r` 删应用目录，同时直接改写 `apps.json` 注册表，最后提示「卸载完成，重启生效」。Chaos 照这个原理做，但用原生文件 API，不依赖 shell。

**三步**

1. **注册表移除**：读 `apps.json` 的 `InstalledApps` 数组，删掉 `package` 匹配的条目并写回；`apps.json_hide` 同样处理。Chaos 已有 `move_vis_to_hide` / `move_hide_to_vis` 的同款 JSON 读写，直接复用；路径按 `DevInfo` 规则选：优先 `/data/quickapp/apps.json`，不存在则 `/data/apps.json`（10 Pro 是后者）。
2. **删目录**（六处，`quickappRoot` 同上规则）：
   - `/data/app/<pkg>/`（应用本体 `app.jsc`、`pages/` 等）
   - `/data/app/<pkg>.old/`（旧版残留）
   - `/data/quickapp/system/<pkg>/`（`usr.db`）
   - `/data/quickapp/cache/<pkg>/`、`/data/quickapp/files/<pkg>/`、`/data/quickapp/mass/<pkg>/`
3. **立即生效**：删完立刻 `app_launcher_del(app_id)` 摘桌面图标 → `reload()` 重读列表，应用从 Chaos 列表和桌面同时消失，**不要求重启**；内存里的旧节点/进程引用属于固件侧残留，等它自己释放或下次开机清掉（Chaos 不再触碰，避免悬空点击）。

**Chaos 实现要点**
- 递归删除：`fw_api::fs::fs_remove` 已处理“文件 unlink、目录 rmdir”两种（内部先 unlink，EISDIR 再 rmdir），深度优先遍历后逐项删；路径固定时也可直接逐条删。
- 安全：包名校验只允许 `[A-Za-z0-9._-]`，拒绝 `/`、`..`；只允许删上述六类前缀 + 包名，绝不接受任意路径。
- **不调用固件 `quickapp_uninstall 0x0C547000`**：那是框架卸载（手机 LAUNCH 消息子类型 3/8），与 SmartHome 的文件级路径不是一回事；§7.1 留作备选。
- 失败处理：路径不存在算成功；`EBUSY`/`EPERM` 记日志并在状态行列出；批量删除逐条执行、状态行显示「删除中 i/N」。
- 成功后同步清理 Chaos 的隐藏名单与排除名单，避免名单指向已删应用。
- 二次确认（5 秒窗口）照旧。

**立即生效 + 重启后干净**：`reload()` 后 Chaos 列表立即移除；桌面图标也已摘；重启后固件扫 `apps.json` 发现应用不在列表，视为未安装，行为与 SmartHome 一致（只是 Chaos 不需要用户重启）。

**代价**：不触发框架卸载回调，运行时可能有残留（已删应用若还在内存里，退出时可能打日志）；因此卸载前先确保应用不在前台/运行，必要时先让它退出，再删文件。悬空节点不主动清理，避免踩到已释放内存。

### 7.1 附：固件框架卸载 API（备选，不采用）

- 手机消息子类型 3 → `0x0C547000(app_id, uri)`；子类型 8 → `0xC548240(app_id, uri, len)`（先比对 20 字节指纹）。
- `0xC547000`：应用运行中（`ctx+0x3B != 0`）→ 置 `ctx+0x3A=1` 挂 launcher 延迟队列；否则 `0xC546F1C` 立即从运行时表 `0x20111B90` 移除（`C8E70F4`），日志 `uninstalled app: %s`。
- 该路径是否删文件未验证，且依赖“应用已停止”，所以不作为 Chaos 的卸载实现。
