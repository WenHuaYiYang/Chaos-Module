# 应用管理：隐藏/显示与免重启模式

> 本文说明 Chaos 应用管理页的两种工作模式、它们改动的文件、固件层依据，以及真机验证清单。

## 1. 固件维护三层状态

| 层 | 位置 | 作用 |
|---|---|---|
| 持久化名单 | `/data/apps.json`、`/data/apps.json_hide` | 开机决定“哪些应用已安装” |
| 内存注册表 | `APP_REGISTRY`（0x200E_B640） | 运行时按包名/app_id 找应用；节点 `+0x08` 包名、`+0x0C` 图标路径、`+0x10` app_id、`+0x3C` bit0 = 应隐藏 |
| 桌面图标 | `LAUNCHER_DESKTOP_LIST` + LVGL 对象 | 用户看到的图标；`app_launcher_del/add` 只改这一层 |

`app_launcher_add`（0x0C51_3A44）先按 app_id 查注册表节点；节点不存在直接返回 0。节点存在才进入建记录回调 `FUN_0C513700`：

```text
ldrb.w r2, [r0, #0x3c]
lsls   r1, r2, #31        ; bit0 = “应隐藏”
bmi    0x0C5137A4         ; 打 “The app need hidden”，返回 0
```

所以：节点不存在时，清 `+0x3C` bit0 根本执行不到，`add` 也不可能成功。

## 2. 模式开关

页 1 顶部有 **“深度隐藏”** 开关，状态保存在 `/data/chaos/appmgr_apply.cfg`（`0` = 深度，`1` = 普通）。

### 普通隐藏（默认，开关关）

- 隐藏：**不动 `apps.json`**，把包名记进 `/data/chaos/appmgr_keep.bin`，置节点 `+0x3C` bit0，再 `app_launcher_del`，立即生效。
- 显示：从名单摘掉，清 bit0，再 `app_launcher_add`，立即生效。
- 开机补偿：维护定时器每隔约 1 秒扫描一次，最多 300 次（约 5 分钟），对名单里的应用重新置位并删图标。
- 代价：开机瞬间图标可能闪现；其它工具读 `apps.json` 会认为这些应用仍可见。
- 排除项坏文件/校验失败时按“空名单”处理：没有豁免项，开机补偿会把 keep 名单里的应用全部隐藏（宁可多隐藏，也不漏隐藏）。

### 深度隐藏（开关开，条目移出注册表）

- 隐藏：条目从 `apps.json` 搬到 `apps.json_hide`，置 bit0，再 `app_launcher_del`；开机固件不注册，图标不出现、不闪。
- 显示：写回 `apps.json`；本机若还能找到节点则清 bit0 后 `add`，否则提示重启。
- **显示需要重启**：条目不在 `apps.json` 时，开机不会建注册表节点，`add` 没有 app_id 可用。
- 与其它工具读写同一份配置的语义一致。

### 切换模式

- 普通 → 深度：把 keep 名单逐条搬进 `apps.json_hide`，回滚失败则整体恢复；迁移完成后提示重启。
- 深度 → 普通：把 `apps.json_hide` 逐条搬回 `apps.json`，同时写入 keep 名单，**保留原有隐藏状态**；迁移完成后提示重启，重启后由开机补偿重新隐藏。
- 切换只改变存储方式，不改变“哪些应用被隐藏”。

## 3. 排除项

`/data/chaos/appmgr_excl.bin`：magic `EX01` + 40 槽 × 44 字节包名。

- 页 1 列表不显示被排除的应用。
- 一键隐藏/显示跳过被排除的应用。
- 页 7 可逐项取消；页 7 的“管理显隐”模式只列排除项，可单独隐藏/显示。
- 排除项与模式开关相互独立。

## 4. 文件一览

| 文件 | 内容 |
|---|---|
| `/data/apps.json` | 可见应用注册表（固件格式，原位改写） |
| `/data/apps.json_hide` | 隐藏应用注册表（同格式） |
| `/data/chaos/appmgr_keep.bin` | 普通隐藏的 Chaos 隐藏名单：`KH01` + 40 × 44 字节包名 |
| `/data/chaos/appmgr_excl.bin` | 排除名单：`EX02` + 40 × 44 字节包名 + 4 字节校验和 |
| `/data/chaos/appmgr_apply.cfg` | 模式开关：ASCII `0` = 深度隐藏，`1` = 普通隐藏 |

## 5. 验证清单

1. 普通隐藏（默认）：隐藏 → 图标立即消失 → 点显示 → 图标立即回来（不重启）。
2. 普通隐藏：隐藏 → 重启 → 图标仍不出现（允许开机瞬间闪现）。
3. 深度隐藏：隐藏 → 重启 → 图标不出现；点显示 → 提示需重启 → 重启后图标回来。
4. 普通切深度：隐藏项迁入 `apps.json_hide`，提示重启；重启后仍隐藏。
5. 深度切普通：隐藏项迁回 `apps.json` 并保留隐藏状态，提示重启；重启后仍隐藏。
6. 排除项：加入后一键操作跳过；页 1 不显示；页 7 可取消。
7. 损坏文件：把 `appmgr_keep.bin` / `appmgr_excl.bin` 写成乱码，页面应正常打开；排除名单损坏时按“空名单”处理，开机补偿会把 keep 名单里的应用全部隐藏。

## 6. 重复条目防护

固件按 `apps.json` 里的每个对象注册应用。同一包名出现两次时，会生成两个桌面记录、两个注册表节点；退出其中一个快应用时资源被二次释放，表现为**右滑退出后黑屏**（系统仍在运行，熄屏/亮屏正常）。

Chaos 现在做三层防护：

1. **写前检查**：隐藏/显示时先看目标文件是否已有该包名，已有就不追加；
2. **一次删净**：移动后把源文件里该包名的所有副本全部删除，而不是只删第一个；
3. **读时收敛**：合并列表里重复的包名只显示第一份（可见优先），一键操作也跳过重复项，页面提示“发现重复条目, 已只显示一份”。

已经损坏的文件：对重复条目点一次隐藏或显示即可收敛为一份；收敛后重启，桌面上的多余图标不会再出现。

## 7. 已知限制

- 开机补偿的闪现时长需要真机录像确认。
- 普通/深度隐藏与米环管理、SmartHome 等工具的交叉行为未验证。
- 固件没有可安全调用的“运行时重新注册本地快应用”入口；`quickapp_register_app` 传入空 `extra` 会在 `strdup(NULL)` 处触发 busfault（已真机复现）。
