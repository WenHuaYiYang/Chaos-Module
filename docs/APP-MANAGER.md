# 应用管理：隐藏/显示与免重启模式

> 本文说明 Chaos 应用管理页的两种工作模式、它们改动的文件、固件层依据，以及真机验证清单。

## 1. 固件维护三层状态

| 层 | 位置 | 作用 |
|---|---|---|
| 持久化名单 | `/data/apps.json`、`/data/apps.json_hide` | 开机决定“哪些应用已安装” |
| 内存注册表 | `APP_REGISTRY`（0x200E_B640） | 运行时按包名/app_id 找应用；节点 `+0x08` 包名、`+0x0C` 图标路径、`+0x10` app_id、`+0x3C` bit0 = 应隐藏 |
| 桌面图标 | `LAUNCHER_DESKTOP_LIST` + LVGL 对象 | 用户看到的图标；`app_launcher_del/add` 只改这一层 |

`app_launcher_add`（0x0C51_3A44）先按 app_id 查注册表节点；节点不存在直接返回 0。节点存在才进入建记录回调 `FUN_0C513700`：

```text
ldrb.w r2, [r0, #0x3c]
lsls   r1, r2, #31        ; bit0 = “应隐藏”
bmi    0x0C5137A4         ; 打 “The app need hidden”，返回 0
```

所以：节点不存在时，清 `+0x3C` bit0 根本执行不到，`add` 也不可能成功。

## 2. 生效模式（页1 的“深度隐藏”开关）

应用管理页行 1 是“深度隐藏”开关，两种模式都可用：

- **开 = 深度隐藏**：隐藏时条目从 `apps.json` 搬到 `apps.json_hide`，开机固件根本不注册，桌面不会先闪出隐藏应用的图标。
- **关 = 普通隐藏**：条目留在 `apps.json`，隐藏状态记在 `/data/chaos/appmgr_keep.bin`；固件照常注册，Chaos 通过节点 `+0x3C` bit0 和桌面图标控制显隐。

模式持久化在 `/data/chaos/appmgr_apply.cfg`（`'2'` + `'0'` 深度 / `'1'` 普通）。配置缺失或损坏时默认深度隐藏。拨动开关只改配置并置请求，真正的迁移在 UI tick 里执行；启动/换绑时按当前模式走对应的补偿路径。

### 深度隐藏

- 隐藏：条目从 `apps.json` 搬到 `apps.json_hide`，置节点 `+0x3C` bit0，再 `app_launcher_del`；下次开机固件不注册，图标不出现。
- 显示：先把条目搬回 `apps.json`；若本机没有注册表节点，调 `quickapp_register_pkg` → 固件 `quickapp_register_app`（`0x0C549678`）从 proxyquickapp 已装表补节点；再清 bit0、`app_launcher_add` 挂图标。补建成功即免重启。
- 开机补偿：`deep_apply_all()` 把 `apps.json_hide`（以及普通隐藏时代留下的 keep 名单）统一搬进隐藏表、置 bit0、摘图标。
- 换绑/重注册：`watch_keep()` 发现注册表包名集合变化后重放一遍深度隐藏。
- 代价/限制：显示依赖 proxyquickapp 已装表已经就绪；表为空或 `quickapp_register_app` 分配 `0xD0` 内存失败时，仍会提示重启一次。

### 普通隐藏

- 隐藏：把包名加入 `appmgr_keep.bin`，条目继续留在 `apps.json`；立即同步节点 bit0 并摘图标。
- 显示：从 keep 名单删除，清 bit0 后 `app_launcher_del` + `app_launcher_add` 挂回图标；不需要搬注册表。
- 开机补偿：`keep_apply_all()` 在节点注册完成后按 keep 名单补隐藏，首次开机会短暂闪一下图标。
- 换绑/重注册：`watch_keep()` 检测到注册表变化后重放 keep 名单。

### 模式切换与迁移

- **普通 → 深度**：`keep` 名单里的条目逐个搬进 `apps.json_hide`，置 bit0、摘图标，然后清空 keep 名单。
- **深度 → 普通**：`apps.json_hide` 的条目搬回 `apps.json`，同时写入 keep 名单保持隐藏；之后普通显示立即生效。
- 迁移失败会按已完成的条目回滚，并提示“切换失败, 已回滚; 请重试”。
- 深度模式迁移后建议重启一次，确保固件开机只读取 `apps.json`。

### 运行期补节点的固件依据（v1.1.12）

- `quickapp_register_app(app_id, info)` `0x0C549678`：分配 `0xD0` 字节上下文并拷贝 `0x2C` 字节 info；再分配 `0x74` 字节节点，填包名/图标、挂链，调用 `app_launcher_add` 加图标，最后 `QUICKAPP_NEXT_ID++`。节点已存在时走更新分支。
- 数据源是 proxyquickapp 已装表，不是 `apps.json`：`0x20111B90` 指向表对象，`quickapp_app_count` `0x0C54A560` 取数量，`quickapp_app_item` `0x0C54A818` 把第 i 项填成 `0x2C` 字节 info。
- 固件自己的重同步：事件 9 回调 `0x0C5498A4` 逐项补缺失节点；手机类型变化入口 `0x0C5499B4(app_type)` 注册回调并（`app_type != 0` 时）遍历全表重新注册。
- 初始化入口 `0x0C548450` 的真实签名是 `(完成回调, 配置串)`，不是无参；配置串会登记到六个事件处理器，传 NULL 会清空它们。Chaos 没有固件启动时那份配置对象，因此**不手动调用**它，只读已装表并等待固件初始化。
- 限制：必须在 UI/tick 线程调用；已装表为空时无 info 可注册；`malloc(0xD0)` 失败会打 `no memory for page.` 并返回 -1。

## 3. 排除项

`/data/chaos/appmgr_excl.bin`：magic `EX01` + 40 槽 × 44 字节包名。

- 页 1 列表不显示被排除的应用。
- 一键隐藏/显示跳过被排除的应用。
- 页 7 可逐项取消；页 7 的“管理显隐”模式只列排除项，可单独隐藏/显示。
- 排除项与隐藏名单相互独立。

## 4. 文件一览

| 文件 | 内容 |
|---|---|
| `/data/apps.json` | 可见应用注册表（固件格式，原位改写） |
| `/data/apps.json_hide` | 隐藏应用注册表（同格式） |
| `/data/chaos/appmgr_keep.bin` | 普通隐藏的 Chaos 隐藏名单：`KH01` + 40 × 44 字节包名 |
| `/data/chaos/appmgr_excl.bin` | 排除名单：`EX02` + 40 × 44 字节包名 + 4 字节校验和 |
| `/data/chaos/appmgr_apply.cfg` | 模式开关：`'2'` + `'0'` 深度隐藏 / `'1'` 普通隐藏 |

## 5. 验证清单

1. 深度隐藏：开关打开 → 隐藏应用 → 重启 → 图标不出现（开机不闪）。
2. 深度隐藏：重启后点显示 → 日志 `显示应用-应用表 N`（N>0）、`显示应用-补建节点 1` → 图标立即回来，不重启。
3. 普通隐藏：开关关闭 → 隐藏应用 → 图标立即消失；重启后仍隐藏（开机会短暂闪一下）。
4. 普通隐藏：显示应用 → 不重启，图标立即回来。
5. 模式切换：普通 → 深度、深度 → 普通各切一次，确认应用仍保持隐藏，日志出现 `模式迁移`，重启后模式仍保持。
6. 排除项：加入后一键操作跳过；页 1 不显示；页 7 可取消。
7. 损坏文件：把 `appmgr_keep.bin` / `appmgr_excl.bin` 写成乱码，页面应正常打开；排除名单损坏时按“空名单”处理，开机补偿会把 keep 名单里的应用全部隐藏。

## 6. 重复条目防护

固件按 `apps.json` 里的每个对象注册应用。同一包名出现两次时，会生成两个桌面记录、两个注册表节点；退出其中一个快应用时资源被二次释放，表现为**右滑退出后黑屏**（系统仍在运行，熄屏/亮屏正常）。

Chaos 现在做三层防护：

1. **写前检查**：隐藏/显示时先看目标文件是否已有该包名，已有就不追加；
2. **一次删净**：移动后把源文件里该包名的所有副本全部删除，而不是只删第一个；
3. **读时收敛**：合并列表里重复的包名只显示第一份（可见优先），一键操作也跳过重复项，页面提示“发现重复条目, 已只显示一份”。

已经损坏的文件：对重复条目点一次隐藏或显示即可收敛为一份；收敛后重启，桌面上的多余图标不会再出现。

## 7. 已知限制

- 开机补偿的闪现时长需要真机录像确认。
- 普通隐藏与米环管理、SmartHome 等工具的交叉行为未验证。
- 固件没有可安全调用的“运行时重新注册本地快应用”入口；`quickapp_register_app` 传入空 `extra` 会在 `strdup(NULL)` 处触发 busfault（已真机复现）。
