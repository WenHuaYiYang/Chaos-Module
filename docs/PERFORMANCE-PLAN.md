# Chaos 性能优化计划

审查日期：2026-11-16。范围：当前 ZIP 源码，10 Pro / 3.101.043。
这是源码审查与实施计划，未取得真机 profile；下文数字分为源码推导与验收目标，不代表实测收益。

## 目标与基线

优先改善点击响应、滑动长帧、启动等待、内存余量与空闲耗电，保留功能与画质。
不能承诺所有场景同时显著提升：蓝牙和快应用引擎可能受固件、无线环境限制。
先记录未加载 Chaos、加载但关闭可选效果、日常配置、全部效果开启四组基线。
固定固件、亮度、表盘、应用清单、蓝牙状态和温度条件，交错重复测试。

采集维护回调及子任务耗时分布、触摸到首个可见反馈、长帧比例、
启动到可交互时间、最小可用堆/最大连续空闲块、图像占用、文件读写次数与字节数、
定时器唤醒次数。耗时在 RAM 中聚合，按需导出，不逐帧写闪存。
续航另做相同条件的长时间测试，不能用短时电量百分比推算。

## 已定位的问题与顺序

### P1：维护任务互相拖累

证据：`watchface.rs::tick_busy` 将任一忙任务提升为全局 50ms 节拍，
其余后台 tick 也会跟着执行；`page/home.rs::needs_tick` 恒真，尽管统计值每秒才更新。
`appmgr/mode.rs::boot_pending` 在补偿完成前持续要求快拍。
补偿每 40 拍重试，最多 300 次：50ms 档下约 600 秒，与注释的五分钟不符。
注册缺失且持续失败时，可能长时间保持快拍。

方案：先将以拍计数的周期改为单调时钟 deadline，再为各任务独立判断到期。
使用最早到期时间调度，输入/请求到来时唤醒；无法验证事件入口时保留低频兜底。
开机重试采用有上限的退避，并把等待下次重试与真正有工作区分。
首页数值更新不再迫使全部维护任务 20Hz 执行。
同一 UI 回调按总预算推进重任务，防止多个分批任务在同一拍叠加。

验收目标：无交互首页维护唤醒减少至少 75%；息屏未收敛补偿不再常驻 20Hz；
普通维护回调 p95 低于 2ms、p99 低于 5ms（需先确认计时器精度与设备可行性）。
不得用延迟触摸响应或延迟安全回收换取唤醒下降。

### P1：应用管理同步文件操作阻塞 UI

证据：`appmgr/detail.rs::detail_open_ctx` 先执行 `scan_size` 和 `scan_version`；
`calc_walk` 同步递归扫描多个候选目录，每层最多 400 项、深度最多 6。
这是规模保护，不是每次回调的耗时预算。`deep_apply_all` 还会解析/迁移注册表并 reload。

方案：详情先展示名称与缓存，大小显示计算中；以目录迭代状态机按时间/条目预算扫描。
以安装版本/变更代数失效缓存，离页取消低优先级统计。
隐藏重放构建一次包名索引，合并文件改写与 reload；保证原子替换、失败回滚和去重。
卸载也采用可中断批次，危险操作确认行为保持不变。

验收目标：大目录应用详情首个反馈低于 100ms，统计期间滑动可响应；
相同清单批量操作的注册表读写次数减少至少 50%，以数据完整性测试为前提。

### P1：动态桌面图标的 I/O、解码与常驻堆

证据：`icon_pack_animation.rs::drive` 在 UI 线程逐个可见播放器读取、解码、切换图像，
每帧后关闭流；维护 tick 和专用动画 tick 都可能调用 drive，帧号比较只能避免重复解码，
不能消除重复可见性查询和元数据解析。
每个 Player 有双像素缓冲、描述符、元数据，分配后在模块生命周期保持。
按 96×96 索引像素、1024 字节调色板、最大元数据推算，每槽约 24KiB，
38 槽被陆续访问后约 0.9MiB，不要求同时可见；实际大小以 ARM size_of 为准。

方案：集中动画时钟，元数据解析一次；按下一帧 deadline 更新。
建立带总内存上限的可见播放器工作集，限制每次 UI 回调的解码工作量并公平轮转。
在已验证的 VFS 语义下评估有界文件句柄缓存、相邻帧预读，避免无限保持句柄。
隐藏/退出后的内存回收必须先恢复 poster、解除描述符引用并完成 GPU/cache 安全退役。
先做内存占用观测，不直接释放仍被固件持有的像素。

验收目标：动画相关峰值堆下降 30% 以上、帧读取 open/close 次数下降 70% 以上，
正常负载保留原帧时序、分辨率和可见动画；超过预算时的策略必须明确记录。

### P2：字体热替换整链扫描

证据：`font_hot.rs::sweep` 每 20 个维护 tick 扫描 wrapper 链，最多检查 4096 节点，
扫描还可能触发每轮最多两个字体构建。扫描频率随全局节拍变化，
动画活跃会间接提高无关字体维护频率。

方案：独立墙钟周期，优先扫描新创建/新换代对象；无法安全挂接创建事件时，
用可验证的增量游标及低频全量校验。节点可能释放或换代，不能跨拍保存未经重新验证的裸指针。
字体构建与扫描分开预算；覆盖新字号、恢复字体、删除在用字体等回归。

验收目标：稳定页面扫描访问量减少 80% 以上，长时间运行后扫描 p99 不随链长线性恶化；
新字号替换延迟不明显退化。

### P2：开关应用的截图与固定动画等待

证据：`quickapp_exit.rs::snapshot` 每次成功退出捕获 336×480×3 字节，约 472.5KiB，
另有两个退役槽；当前快照加两个未回收快照仅像素就可能约 1.38MiB，另有原生过渡资源。
`quickapp_splash.rs::launch_ready` 桌面冷启动需首帧通知且至少 240ms 才提交引擎，
因此动画顺滑不等于更早可交互。上一轮修复只解决非桌面启动被丢弃。

方案：测量截图、GPU 等待、原生过渡各自耗时；先优化快照退役和有界复用。
低内存或 GPU 繁忙时维持已有正常退出回退。
冷启动优先研究让原生请求在合法的 UI 时序下更早提交；引擎同步阻塞时需先证明线程与
页面生命周期可行性，不把固件 UI 调用直接挪到工作线程。
若仍需等待动画结束才能加载，明确它是视觉效果与启动延迟的取舍。

验收目标：启动到可交互时间相对当前动画开启场景缩短至少 20%，退出峰值堆下降 30%；
连续开关 100 次无黑屏、重复启动、泄漏或图像提前释放。

### P2：模糊与后台图形任务争用

项目已具备相同采样帧复用、插值优化与部分冗余 invalidate 消除，见 PERFORMANCE.md，
这些不计作新成果。即使像素不变，要发现不变仍可能先发生采样与 GPU 同步，需实测定位。
方案：记录捕获、等待、滤波、放大、发布各阶段；来源及几何代数无变化时优先避免采样，
保留会变化但没有可靠脏通知的内容的低频检查；合并同一来源的重复处理。
不得删除 GPU fence 或缓存同步来提高表面跑分。

验收目标：静态背景无效采样减少 80%；动态滑动长帧减少 30%；画质参数保持一致。

## 实施批次与回归

1. 建立测量与场景基线，先恢复 Rust nightly、Python、交叉编译及 ARM 探针环境。
2. 低风险批次：独立 deadline、开机退避、首页低频更新、详情渐进统计。
3. 中风险批次：批量注册表处理、字体增量扫描、动画 I/O 与内存预算。
4. 高风险批次：截图复用、GPU 争用和启动动画生命周期，逐项发布与真机回归。

每批独立构建并与上一批对比，至少测试首页、桌面、快应用冷/热启动、普通/深度隐藏、
换绑/安装、字体切换、新字号、连续进退、息屏/AOD、蓝牙传输和动画叠加。
蓝牙仅在 profile 显示 Chaos 侧解析/调度占比足够大时进一步优化；不能承诺无线吞吐翻倍。
模拟器用于逻辑、ABI 和内存安全，最终收益由真机耗时/堆/功耗证明。

上线门槛：目标场景有统计上稳定的改善，非目标场景无明显退化，功能与画质保持，
资源安全测试通过；没有实测支撑的百分比仅作为目标，不写入发布收益。

## 模糊卡顿专项（追加审查）

### 已确认的额外成本

- `p67_blur_native.inc::p67_blur_native_copy` 每次采样分配 336×480 BGR888 截图，
  截图前后有 GPU fence，且包含 cache clean/invalidate、降采样和 V2 颜色采样。
  相同采样帧缓存命中发生在这些采样工作之后，不能免除前段成本。
- `p67_blur_native_publish` 每次成功创建新输出描述符；V2 输出仍是 336×480 BGR888，
  `chaos_v2_store_full` 负责写入全尺寸输出。一次输入和一次输出像素写入的规模
  各约 472.5KiB；这不是精确总带宽，未包括快照绘制、读输入、缓存维护和 GPU 消费。
- `control_center_buttons.inc` 的 `cc_update` 在帧更新时可以执行 fence、atlas 复制和 flush。
  已有半分辨率同纹素跳过，但跨纹素的按钮移动仍可能进入复制路径。
  此函数已经在一轮按钮更新中共享 fence/flush，不能把逐按钮合并再算成新优化。

### 专项实施顺序

1. **阶段计时与归因**：在 RAM 聚合 COPY 前等待、快照、COPY 后等待、降采样、
   滤波、全屏放大、分配/发布、按钮更新耗时；区分桌面、控制中心、通知、小组件。
   动态表盘/静态表盘与按钮效果开/关分别比较，不把全部模糊作为单一开关归因。
2. **采样请求合并**：同一来源代数只保留最新请求；背景/按钮共享同一份捕获。
   来源未变且无待更新内容时不再次捕获；可靠变化信号缺失时保留兜底采样。
   参数变化尽量从已缓存的原始缩略图重算，而不重新截图；根对象换代必须失效。
3. **缓冲复用**：评估固定大小输入槽与双/三输出槽，稳态不再每帧分配释放。
   以引用状态和 GPU 完成状态选择可写槽，无空槽时保留上一张完整发布图，
   不覆盖在途纹理。设置总内存上限，避免用更多缓冲换取不可接受的常驻堆。
4. **滑动帧路径减负**：按钮优先用 GPU 的共享 atlas 与裁剪/纹理坐标表达位移，
   减少按位置 CPU 拷贝。须验证固件 VG-Lite 对裁剪、缩放、圆角 alpha 和坐标边界的支持；
   不支持时保留现有路径。不要把安全 fence 简单删掉。
5. **低分辨率滤波输出由 GPU 放大**：当前路径 CPU 写满 336×480；评估让 GPU 采样
   缩略纹理完成放大，避免 CPU 每次写全屏。像素中心、插值、边缘和颜色格式必须对照；
   当前 CPU 插值与 GPU 结果未证明等价，不能声称此项无画质变化。
6. **可选交互优先模式**：若上述同画质优化后仍超预算，手势期间保持最近完成的背景，
   前景和几何正常跟手，松手后立即补最新背景；或者限制背景更新率。
   这是模糊背景实时性的明确取舍，应作为可选模式，不计为无损优化。

### 验收

固定模糊参数与表盘，对每个区域连续滑动、开关、跨页及息屏唤醒测试。
同时记录长帧数量、p95/p99 帧耗时、触摸响应、捕获/分配/fence 次数和峰值堆。
优先目标：静态来源捕获数下降至少 80%，稳态全屏分配接近零，
滑动长帧数下降至少 30%；最终以真机结果调整目标。
还需运行现有 `test_performance.py`、`test_corona_blur.py`、`test_blur_v2.py`、
`test_cc_buttons.py` 和相应 ARM 探针，覆盖切换算法、根对象删除、发布失败、
GPU 忙、槽位耗尽及关闭后的安全退役。
