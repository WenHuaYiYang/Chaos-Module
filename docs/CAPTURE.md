# 截屏与录屏

首页进入“截屏与录屏”，二级列表依次为：

1. **开始录屏**：点击后变为“结束录屏”。返回首页或离开 Chaos 页面不会停止录制；再次点击结束后等待保存完成。
2. **管理录屏**：三级文件列表，管理 GIF/APNG 文件。
3. **遮盖截屏**：点击后等待息屏（OFF 或 AOD），随后读取 framebuffer 并保存 BMP；等待中再次点击取消，60 秒未息屏则超时取消。此项不主动关闭屏幕。
4. **管理截屏**：三级文件列表，管理 BMP 文件。
5. **录屏设置**：格式选择 **GIF · 15 fps** 或 **APNG · 60 fps**；储存路径选择 `/data/chaos/media` 或 `/data/offlinelog`。
6. **截图设置**：独立选择截图储存路径 `/data/chaos/media` 或 `/data/offlinelog`。

底部分别显示当前录屏和截图的储存路径。默认沿用 GIF 15 fps、两者均存入 `/data/offlinelog`。设置保存在 `/data/chaos/capture.cfg`，校验写入并重命名后才生效；保存失败保留原设置。录屏开始时固定本次格式及路径，遮盖截屏布防时固定本次路径，期间调整只影响下一次操作。

两个管理列表均汇总两处目录，文件副标题以“媒体”或“日志”区分位置。每页 8 项，有上一页、下一页和刷新；第一次点击文件显示“再次点击删除”，第二次点击删除该位置的文件。取消确认可点刷新或另一文件。录制中隐藏正在写入的临时文件；重启遗留的 `.part` 可在空闲时删除。

## 格式与范围

- 录屏均为 **336×480、无声音、RGB332 索引调色板（中性灰阶纠偏）**。GIF 使用 15 fps 的分数周期采样和百分之一秒延时；APNG 优先由显示同步唤醒、通知缺失时按时间补采，使用毫秒延时，优化目标为 60 fps。实际帧率取决于显示更新、CPU 和闪存吞吐，尚无真机帧率结果。
- 静止画面合并为上一帧的停留时间，变化画面只编码最小包围矩形；息屏期间暂停采集，保留停留时间。负载高时选择当前可用画面，不追补已经错过的采样时间点，也不生成虚假的中间帧。
- **宽松采集**：完整读取的 framebuffer 快照直接用于量化，不因窗口变化反复丢弃。首份复制的测量耗时不超过 4 ms，且期间收到显示同步时，立即重取一次较新快照；不再等待下一次同步。只允许这一次重取，慢复制保持原快照；无复制后的 plane-info 查询。同步只是唤醒提示，通知缺失或合并时也能按时间采集。仍检查布局、窗口边界和实际读取字节数；真实读取、写入、关闭或重命名错误仍报错。此策略在保留宽松采集的同时减少部分撕裂，无法保证完全消除；改善程度需要真机验证。
- 录制页显示**实际平均采集率**，统计实际采集快照而非静止合并后的文件帧数。这是观测值，不等于播放器帧率或稳定 60 fps 保证。
- **灰阶纠偏**：原 RGB332 调色板把灰色 `(48,48,48)` 展开为 `(36,36,0)`，导致灰色卡片泛黄。GIF/APNG 现在共用一张调色板，仅修正六个中性格子的蓝分量，使所有纯灰输入保持 R=G=B。像素索引计算不变，不增加逐像素处理；RGB332 仍有色阶和精度限制。
- 截图为 24 位 BMP，336×480，保留原始颜色。
- 文件名为 `chaos-rec-<启动秒数十六进制>-<序号>.gif` / `.apng` 或 `chaos-shot-<启动秒数十六进制>-<序号>.bmp`，放在选择的目录。只管理严格匹配 Chaos 命名的普通文件，不递归删除其他文件。
- 单次录屏最多 5 分钟或约 16 MiB，先达到者结束并保存。可读到 `/proc/fs/usage` 的 `/data` 余量时保留约 2 MiB；余量不足会拒绝开始或自动结束当前录屏。不能读取余量时仍检查实际写入结果。
- 文件先写 `.part`，成功写入结束标记、关闭并重命名后才作为完成文件出现。没有有效首帧时删除空文件。分配、读取、写入、关闭或重命名失败会报告错误并清除临时文件；突然掉电可能留下 `.part`。
- 原缓存清理会遍历 `/data/offlinelog`；现在保留 Chaos 录屏、截图及临时文件，交由管理页删除。

## 实现

`capture.rs` 使用一个常驻 NuttX task，UI 只发布原子请求及读取状态，worker 不调用 LVGL。worker 持有约 473 KiB BGR 快照、两块约 158 KiB 索引帧、16 KiB 输出缓冲及 44 字节同步状态；GIF 另用约 48 KiB LZW 字典。动态缓冲均在堆上，结束后释放，任务栈为 32 KiB。息屏截图可复用录屏快照，单独截图时临时分配并立即释放。

每次采集通过原生 `fb_read` 批量复制可见窗口，再量化私有快照，避免边读取活跃 framebuffer 边逐像素量化造成长时间跨同步。原生读取完成规定字节数后保留快照，不用复制后的地址/yoffset 变化判废。快速复制跨同步时只允许一次即时重取，第二次仍跨同步也接受完整结果；首份复制超过预算或已息屏时不重取。通知序号跳跃只累计诊断，最后通知合并到本次，避免反复读屏。编码后读取当前画面，不使用会在拥堵时自动结束的帧队列。

GIF 以 15 fps 分数周期限速，达到期限即可采集，不强制等待新同步。APNG 优先跟随同步唤醒，首帧直接读取；没有新通知且距上次采集至少 17 ms 时允许计时补采。短暂等待返回后不再叠加一次休眠；相同时间反复检查不会持续读屏。内核 tick、CPU 和存储速度仍会影响实际帧率。OFF/AOD 时确认已有通知并暂停后续采集。

两种格式按行比较索引画面，合并相同帧、编码变化区域。一帧前瞻确定实际停留时间后顺序写入；GIF 携带累计百分之一秒取整误差，APNG 使用毫秒有理数，结束时只回写一次 `acTL` 帧数及 CRC。GIF 内联字典查询和位输出，APNG 的单字节字面量直接编码，减少高变化区域的函数调用。输出缓冲 16 KiB，余量每秒检查一次。

`capture_format.rs` 提供 GIF/BMP、共享的中性灰纠偏调色板、索引比较和严格路径校验；`capture_apng.rs` 提供 APNG、CRC32、Adler32 和流式压缩；`capture_settings.rs` 保留 CAP2 格式、独立路径及录屏格式设置。`page/capture.rs` 提供五个注册页（38–42）。

固件接口仅面向 p67 / **3.101.043**：原生 AT 截图命令在 AP 文件 `0x5EDBC0` 使用 `dd if=/dev/fb0 … bs=483840 count=1`；原生显示初始化在 `0x3F7AA4` 调用 ioctl `0x2801`，fmt=12 映射 LVGL RGB888（BGR 内存顺序）。打开时检查 336×480/fmt=12，采集时检查 plane info 的 stride=1008/bpp=24、虚拟高度及可见窗口边界，拒绝其他布局。原生 `fb_read` 在 AP 文件 `0xEF0A6` 调用批量 memcpy thunk `0x0C588DB1`，最终转到 ROM `0x00276661`。BMP 截图也通过设备读取，不依赖已停止的同步信号。

垂直同步依据：AP 文件 `0x166410` 的显示服务调用 `fb_notify_vsync`（执行地址 `0x0C1AF91C`），发送 `POLLPRI=2`。采用原生 `file_poll`（`0x0C1D0BA5`）注册独立回调；`fs_getfilep`/`fs_putfilep` 为 `0x0C1B9701`/`0x0C1B979D`。此固件的 `pollfd` 是 **24 字节**。回调确认事件位并递增原子序号，交给固件原生 poll 唤醒回调 `0x0C1D0B15`，以 IRQ 安全的信号量唤醒 worker；重复通知合并为最多一个令牌。状态分配在稳定堆地址，解除订阅后才释放。

APNG 等待原生信号量时，显示同步可立即唤醒，等待上限为一个内核 tick，便于息屏和停止时退出。未调用可能无限等待的 `FBIO_WAITFORVSYNC=0x2808`。计时补采不依赖新同步，等待期间仍可取消；始终处于息屏且没有有效首帧时，结束会报告未获取到画面并删除空文件。

## 验证与边界

```sh
# Rust 和 Pillow；实际 worker + VFS/调度模型，独立解码
python3 tools/test_capture.py
# 精确固件静态接口核对（固件不随源码分发）
python3 tools/verify_capture_abi.py /path/to/vela_ap.bin
# 真实固件 file_poll/fb_poll/通知、原生信号量和解除路径；需要 Unicorn
python3 tools/probe_capture_vsync.py /path/to/vela_ap.bin
# 主机合成编码开销，不是设备 FPS 测试
python3 tools/bench_capture.py
python3 tools/build.py
```

40 项主机测试覆盖生命周期、设置、双目录管理、短写和错误、空间/时长限制、静止合并及时间轴。新增 256 级纯灰中性检查、两种录屏格式的灰色卡片和基本色通道解码、持续切换时最多一次重取以及慢复制不重取。Pillow 独立解码验证灰色 `(48,48,48)` 不再呈黄绿，并核对修复采样采用较新画面的像素、顺序及总时长；Python zlib 验证 APNG CRC、序号与压缩流。原有无同步计时补采、采样有界、时钟回绕及慢写回归继续通过。硬件撕裂和帧率仍需真机复测。

Unicorn 探针执行精确 AP 的 `file_poll → fb_poll → poll_notify`、原生信号量初始化、原生 poll 唤醒回调及解除订阅，检查稳定地址、通知合并与解除后不再调用；另执行 `fb_read` 验证两个 483840 字节窗口、文件偏移和 EOF 边界。Rust 回调、显示信息提供函数、ROM memcpy 及内核调度叶节点仍使用模型，硬件、DMA、IRQ 调度和实际帧率尚未验证。

仍需 p67 真机验收：页面显示与手势、实际录制帧率、RGB/方向、息屏时 framebuffer 是否保留期望画面、深度休眠、长时间写入及异常恢复。编译和主机测试不能替代这些硬件验证。
