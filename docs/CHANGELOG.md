## v1.2.7-4a6a33ed — 修掉省电模式反而 95% CPU 的抖动（2026-11-21）

实测：不开省电 20–30%（已达标），开省电反而 **95%**。三个"恒真忙判定 + 过度节流"
叠加造成的抖动，逐个收口：

- **`notification_icon::pending()` 把"功能启用"当"有活"**：ACTIVE 一旦开过就恒真，
  `background_home::pending()` 跟着恒真、`tick_busy` 永远为"忙"，节拍降不下来；
  与 1s 节拍组合时来回抖动。新增 `busy()`（只在重试未清零或还持有图源时为真），
  维护节拍改用它。
- **`s541_launcher::pending()`**：控制条在桌面"可见"就要求 50ms 快拍 —— 只要停在
  桌面整机就永远 50ms。极致省电模式下让它让路（跟随滚动略钝，是省电模式接受的代价；
  关掉开关立即恢复跟手感）。
- **节拍 1000 → 600ms、poll 间隔 4 → 2**：1s 节拍会把"20 拍重试"这类拍数逻辑
  拉成 20 秒，期间 busy 反复翻转、定时器在 50ms/1s 间抖动；4 秒一次 poll 还会让
  模糊 owner 心跳超时、上游反复重建整屏纹理。宁可少省一点，不能引发抖动。

## v1.2.7-4ca9224d — 按钮模糊默认关闭；不用截图则零周期成本（2026-11-21）

按实际使用习惯收口：**按钮模糊与截图都不主动使用**，那就别让它们付任何代价。

- **控制中心按钮模糊 / 启动器按钮模糊默认改为关闭**（配置项仍保留，需要的人去
  系统美化 → 模糊区域 手动开）。开着它们等于给模糊引擎一个恒真的"有需求"，
  每帧都要合成一层纹理 —— 这是合并后静置 CPU 升高的主因。
- **截图缩略图 poll 加快速路径**：九个头图槽全空且没有在跑的活时直接返回，
  从来没截过图的人一拍都不为它花。
- 极致省电模式仍会强制关闭这两处按钮模糊（双保险）。

## v1.2.7-74dc527d — 修复合并后静置 CPU 反而升高（2026-11-21）

融合上游 1.27 后发现静置 CPU 比合并前更高、且开极致省电也无效。两个根因都在上游新功能：

1. **`tick_busy` 无条件计入截图缩略图的 `pending()`**：缩略图槽 `status==0` 会在离开
   截图 App 后残留（无人推进），而 `FG_PAGE` 仍停在截图页 → 每拍都返回"忙" → 整机
   永久 50ms 快拍，省电模式的节拍设置被完全绕过。现在加 **`APP_FG != 0` 门**：只有
   截图 App 真的在前台时才为缩略图加快节拍。
2. **上游新增的「控制中心按钮 / 启动器按钮」模糊默认开启**，它们让
   `P67_BLUR_EXTRA_DEMAND()` 恒为真 —— 模糊引擎永久"有需求"，节拍/poll 降频对它
   无效。现在**极致省电模式下强制关闭这两处按钮模糊**（关掉省电模式即恢复原设置），
   并且 `cc_buttons_poll` 也纳入空闲降频（原本每拍都在查 root/像素）。

## v1.2.7-e65c27ad — 极致省电模式（2026-11-20）

实测标准档静置 CPU 从 60–70% 降到 43–50%，仍偏高。这一版把更激进的降频
做成**实验性开关**，默认关闭，用户自己决定：

- **设置 → 实验性功能 → 极致省电模式**（新增开关，持久化到
  `/data/chaos/power_saver.cfg`）。
- 开启后：
  - 维护节拍中档 **400ms → 1000ms**（稳定态 1Hz）；
  - Corona 上游 poll 空闲倍数 **2 → 4**（约 4 秒一次观察者/描述符校验，
    display/launcher rebind 也一起降频）；
  - 通知图标扫描空闲跳拍 **8 → 12 拍**。
- 有活时（装配、滚动、采集未完成、失败恢复、待重绘）仍全部走 50ms 快拍，
  功能正确性不受影响；代价只是模糊自愈、通知变化、后台页刷新的响应从
  亚秒级变成秒级。
- 页面附说明文字，讲清代价是什么。

## v1.2.7-c0ebd5f — 静置功耗与 CPU 优化（2026-11-20）

版本串改为带**构建号**（`v1.2.7-c0ebd5f`，构建号 = 构建时的 git 短哈希，
工作区有未提交改动时追加 `d`）。只改 `tools/p67_pack.py` 的 `VERSION_BUILD` 一处，
产物文件名、关于页、连接日志同步；安装器标题保持 `Chaos127安装器` 单行可读。

针对实测「静置约 10 分钟一格电、CPU 60–70%」的三处降频：

- **通知图标扫描空闲跳拍**：`notification_icon::tick` 每拍深度遍历 8 层通知树，
  即使没有任何通知。现在上一轮扫完且无改动时，每 8 拍才重扫一次
  （静置扫描频率 5Hz → 0.6Hz）；发现变化或扫描不完整立刻恢复每拍。
- **Corona 上游 poll 空闲降频**：`rh_platform_backgrounds_poll`（观察者/描述符
  校验 + 三个 surface 的通知列表遍历）稳定态每 2 次 poll 才完整跑一次；
  采集未完成/待重绘/刚装配/冷却/交互中仍每拍，恢复速度不变。
- **维护节拍中档 200 → 400ms**：亮屏无活的稳定态唤醒 5Hz → 2.5Hz。
  有活时仍走 50ms 快拍（装配、滚动自愈、失败恢复都不受影响）。
- **V2 默认背景采集间隔 500 → 800ms**（V2 档本来就是"费电档"，降低重采频率）。

预计静置 CPU 显著下降；V3 档（场景门控）静置基本不再采集。

## v1.2.7-Alpha — 蓝牙名、模糊功耗、流畅度、缺陷修复与 V2/V3 双档（2026-11-19）

本版基于 v1.2.6 合并发布；早期构建曾添加 `Alpha` 后缀，现已恢复从 Cargo.toml 读取版本号。

### 实机问题

- **不再改写手环的本地蓝牙名。** `bt_probe.c` 的 `prepare()` 之前每次发 `cmd 0x22`
  把 adapter 名强制写成 `Chaos-Module`，系统设置里改回来也会被覆盖。改名与 PAN 配对无关，
  已整条删除，只保留 `cmd 0x23` 回读供诊断页显示；诊断页对应一行改为「名保持系统」。
  以前被改过的机器升级后重启一次即可恢复。
- **修复开启模糊后 CPU 占用接近 100%（自激采集环）。** 周期采集判据原先用
  `p67_blur_draws`，但采集本身会请求整屏重绘、又抬高计数，形成
  「采集 → 整屏重绘 → 计数+1 → 再采集」的自激环。现改用场景身份判据
  （表盘 identity 变了才重采），并给卡住的采集加放弃阀（超 1.5s 放弃并冷却 3s）。

### 模糊 V2 / V3 双档

系统美化 → 系统模糊为三选一：`系统背景`（关闭）/ `模糊 V2` / `模糊 V3`。

- **V2 保持原样**：SysPatch 四方向 IIR（radius 12、每像素色彩 LUT、全分辨率
  336×480 BGR888 ≈ 484 KB 纹理），按 `BP_BG_INTERVAL`（默认 500ms）周期重采。
- **V3 = V2 的画质 + 省电改动**：场景身份判据切断自激环、卡住兜底、
  维护节拍不再被模糊常驻占用（50ms → 200ms）。静止桌面基本不再产生采集与整屏重绘。
- 升级迁移：旧 `blur_v2.cfg` 为 1 时自动落到 V3；新配置写在
  `/data/chaos/blur_algo.cfg`（0=关，1=V2，2=V3）。

### 交互流畅度

- **桌面滑动期间冻结图标动画。** 动态图标逐帧解码在 UI 线程上与滑动手势抢帧时间。
  新增 `launcher_scrolling()`（只读滚动量），滑动中及停稳 160ms 内跳过解码与上传，
  保留帧定时器与播放相位，停稳后接上。
- **主维护节拍不再被图标动画绑定在 50ms。** 预载改由动画独立帧定时器驱动，
  稳定态回落 200ms。

### 缺陷修复

**应用管理（数据安全）**
- `rewrite::serialize` 追加路径会写坏 `apps.json`（写指针越过读指针导致非法 JSON，
  桌面应用全丢）；追加前检查空间，不够就明确失败回滚。
- 注册表无 `InstalledApps` 数组时补出数组再追加，不再静默丢弃。
- 排除名单读失败进入只读降级并按 5s 退避重试，不再用空名单覆盖磁盘；
  修掉校验和处未对齐 u32 读（Cortex-M UB）。

**灵动点**
- 截图排队后息屏导致 `SHOT_STARTED` 永久置位、圆点输入全部失效；现在无条件清标志。
- 结果提示期间全屏 scrim 会吃掉第一下点击；scrim 只服务三级菜单。

**灵动点（透明度可自定义）**
- 「半透明显示」开关升级为「透明度」行：点击在五档间循环——不透明度
  100% / 83% / 67% / 50% / 33%，点击即保存并原地刷新该行。配置沿用 `DOT2`
  byte[6]，旧文件 0/1 自动映射（关=100%，开=83%），无迁移损耗；校验放宽到 0..=4。
  渲染两处都按档位取值：球体底色 alpha（255/212/170/128/85）与弧带未填充
  alpha（255/158/130/100/70），弧带文字层透明度沿用同一档位。

**图标 / 触控点**
- 图标恢复节点暂时缺失时保留 `IC_SAVED` 记录，图标不再永久无法还原。
- 触控点参数非法时不再误清 `SAVE_FAILED`。

**ChaosConnect / 网络**
- 构建脚本补上 `--wrap=bt_probe_connect_address`，「记住的对端直连」恢复工作。
- 文件桥启动失败改为最多 3 次退避重试（5s/10s），到顶写终态并记日志。
- 凭据只在还没有时播种默认值，不再把用户改过的密码重播回 `chaos/chaos`。

**快应用**
- 开启快应用启动动画后划回桌面会卡在动画页点不了：遮罩只在「前台不是桌面」时撤，
  划回桌面正是最常见退出方式。现在记录「是否到过前台」，到过又不在立刻撤；
  从没到过给 3s 冷启动宽限。

### 蜂窝桌面（实验后已回退）

### 版本号来源

`supervisor/Cargo.toml` 的 `[package].version` 是唯一版本来源。
关于页和连接日志通过 Cargo 的 `CARGO_PKG_VERSION` 读取；Python 与 Node 打包脚本也读取同一文件，
将主、次、修订号映射到容器头。没有独立版本常量或自动追加的 Alpha 后缀。
当前为 `1.2.7`，修改版本号只需修改 Cargo.toml。
