# 桌面 / 控制中心模糊滑动卡顿专项

> 历史记录（2026-11-16）：保留当时基线与阶段结果；当前行为、取舍和验证边界见 [性能说明](PERFORMANCE.md)，记录目录见 [历史索引](history/README.md)。

适用：小米手环 10 Pro / p67 / 固件 3.101.043。包含此前首页统计空白与快应用打开修复。

用户反馈：桌面和控制中心均启用模糊时，滑动仍明显卡顿。
此前 CPU 颜色与采样遍历优化没有移除交互帧中的快照、GPU 等待和按钮纹理搬运。
本次改为交互期间复用已完成纹理，在稳定后更新。

## 行为

- 在现有、身份与代数校验后的 launcher / 面板事件中观察 SCROLL_BEGIN、SCROLL、SCROLL_END。
- 控制中心额外观察按钮实际坐标变化，覆盖列表滚动和惯性位移；观察坐标独立于
  已发布纹理坐标，避免因旧纹理位置不变而让等待永久延长。
- 最近一次位移/滚动事件后 160ms 内，模糊 START 不执行新的截图、滤波、发布；
  READY 不因待处理模糊反复请求重绘。已有背景仍照常绘制，更新请求保留。
- 控制中心这段时间仍绘制已就绪按钮纹理，跳过额外纹理复制、fence、flush 和完整性扫描。
- 稳定 160ms 后沿现有维护/渲染链处理最新状态，合并期间请求，不补播积压帧。
- 缺失 END 也会按静默超时恢复；时钟回绕已测试。
- DELETE 继续立即撤销逻辑所有权；关闭模糊后的资源回收绕过交互门控，保留原 GPU 安全机制。

取舍：滑动时动态表盘生成的模糊背景暂缓变化；按钮内的玻璃采样暂时随按钮移动，
稳定后重新对齐背景。这不是降低分辨率、模糊强度或全局动画帧率，
但确实降低了交互过程中模糊内容的实时更新程度。
初次没有已发布纹理时，也可能要等手势稳定后才出现首张模糊图。

## 测试与限制

- `tools/test_blur_interaction.py` 使用生产 blur START/READY 与按钮更新代码、原生调用替身：
  连续 120 个手势帧没有新增截图/发布/模糊唤醒，待处理请求保持；
  连续 120 个按钮移动帧仍绘制缓存图，没有额外按钮更新 fence/copy/flush/scan；
  静默后更新一次，并测试关闭回收和时间回绕。
- 通过 `test_corona_blur.py`、`test_cc_buttons.py`、`test_home_stats.py`、
  `test_blur_v2.py`、`test_blur_params.py` 和像素/性能回归。
- 完整 ARM 编译和 ELF 检查，零未定义符号。

以上为宿主逻辑与生命周期测试，不能证明设备端帧率或整个系统没有 GPU 等待。
实际手感、原生事件覆盖、首帧效果仍需真机复测。
没有进行不安全的 GPU fence 删除，也没有修改官方触摸/滚动算法。

请安装文件名带 `blur-scrollfix` 的新包。若重新进入页面后首页统计仍异常，
或滑动时出现缺失背景/花屏，应保留现象用于下一步定位，不把宿主测试结果当作真机结论。
