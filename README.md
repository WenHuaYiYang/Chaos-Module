# Chaos —— 小米手环 10 Pro 上的原生应用平台

一个 `no_std` 的 Rust 内核模块，加一个 Lua 安装器。它借固件自己的注册链把**原生应用**
装进手环桌面：launcher 里多出一枚 Chaos 图标，点进去是固件原生的页面、原生控件和原生
转场动画。运行期间不联网、不依赖手机，也不改动固件分区。

- 目标设备：小米手环 10 Pro（内部代号 p67）
- 目标固件：**3.101.043**。更早固件的地址与产物全部不适用，别拿这份代码去跑旧固件。
- 设备侧零第三方依赖，只用 Rust 核心库和固件自带的 API。
- 许可：AGPL-3.0，全文见仓库根的 `LICENSE`。

## 手环上能用什么

装完之后桌面多一枚图标，进去是一个主页加十三个二级页：

| 功能 | 说明 |
|---|---|
| 系统信息 | 存储、内存、CPU 实时读数，存储与内存带进度条 |
| 文件管理 | 浏览设备文件系统到四级目录；文本分段读，二进制按 strings 提取可打印串 |
| 表盘 | 列出内置与市场表盘，点选即切；勾选哪些表盘参与摇一摇轮换；摇一摇总开关 |
| 亮度 | 手动调亮度、自动亮度开关 |
| 缓存清理 | 统计可清理项并一次清掉 |
| 更换字体 | 投进设备的字体列成复选框清单，点一下就换、不用重启，支持两步删除 |
| 桌面图标 | 替换桌面 38 个应用位的图标（当前固件里实际存在 35 个），可一键恢复系统原图标 |

字体和图标走的是同一套机制：素材打成一个 `.bin` 投进设备，模块读清单、分批替换，
全程不重启。细节见"字体与图标投递包"。

## 从源码到设备

### 环境要求

| 组件 | 说明 |
|---|---|
| Rust nightly | 需要 `-Z build-std`，stable 不够 |
| `rust-src` 组件 | `rustup component add rust-src` |
| `thumbv8m.main-none-eabi` | Cortex-M33 软浮点目标 |
| `rust-lld` | nightly 自带 |
| Python 3 | ELF 后处理与产物校验 |

### 第一步：编出静态库

```bash
cd supervisor
RUSTFLAGS="-C target-cpu=cortex-m33 -C target-feature=-fpregs" \
  cargo +nightly build --release --target thumbv8m.main-none-eabi \
    -Z build-std=core,compiler_builtins
```

产物在 `target/thumbv8m.main-none-eabi/release/libchaos_sup.a`。

那两个 flag 不是风格问题。手环 SoC 没有浮点寄存器，硬浮点编出来的模块 ELF 属性跟官方
产物不一致，加载器不认。目标是让 `e_flags` 与 `.ARM.attributes` 对上官方模块。

### 第二步：合成可重定位 ELF

```bash
rust-lld -flavor gnu -r --gc-sections \
         -u module_main -u chaos_ctor \
         -T merge_sections.ld \
         -o chaos_sup.ko libchaos_sup.a
```

四条各有原因，缺任何一条都得到"加载了但不干活"的模块：

- `-r`：产出可重定位 ELF。Vela 的模块加载器要的是这种，不是可执行 ELF。
- `--gc-sections`：控体积。`-Z build-std` 下每个函数一个段，不 GC 会把 `core` 的整个
  `.text` 拖进来，实测涨到 550 KB 左右，超过 `insmod` 的 256 KB 上限。
- `-u module_main -u chaos_ctor`：强制保留两个入口。它们没有调用方，`--gc-sections`
  会当垃圾收掉。
- `-T merge_sections.ld`：把 `.text.*` 合并成一个连续段，并丢弃 `.llvmbc`。
  `rust-lld -r` **不会**自动合并，漏了这一步 `.text` 大小为 0，模块加载进来但里面
  一条指令都没有。

### 第三步：重排节区，然后校验

`rust-lld -r` 产出时所有节的 `sh_addr` 都是 0。Vela 加载器按这个值摆放内存，结果是
`.rodata` 叠在 `.text` 上，症状是切表盘时崩溃。修法是把各节 `sh_addr` 重写成连续布局。

重写之后校验一件事：**未定义符号必须为 0**。这个模块没有能解析外部符号的链接阶段，
留一个未定义符号就等于运行时跳进随机地址。

### 第四步：打包与刷入（这一跳还没发布）

模块、安装器 Lua、应用图标要打进一个表盘容器 `.bin`，手环把它当成一枚第三方表盘收下来。
打包脚本与容器壳目前不在本仓库，见"当前发布状态"。

重要：这条链**不能重复执行**。旧模块还在内核里时，安装器会在"加载模块"那一步主动失败
并提示先关机再开机 —— 这是设计，不是缺陷。固件注册链表的条目在模块被卸载后会悬空，
之后 launcher 遍历到它就崩，所以宁可要求重启，也不做卸载。

## 工作原理

```
Lua 安装器（跑在固件的表盘 Lua 运行时里）
   |  把模块、图标、字体落到 /data/chaos
   |  insmod chaos_sup.ko
   v
chaos_sup（常驻内核模块，持有设备节点 /dev/chaos）
   |  从设备文件收命令，调固件的注册链
   v
注册应用 com.chaos.manager -> launcher 出现图标 -> 点图标进入页 0
   |
   v
14 个页面由模块里的 PAGE_TABLE 提供 on_create / on_destroy / event
```

安装器每走一步都要让出一个 `lv_timer` 拍，让固件事件循环完整转一圈再走下一步。
注册链的中间态如果在同一拍里被读到会出错。

## 安装容器格式

容器 magic `0x1234A55A`，布局：

```
[0x000-0x147 头部与主题表] [0x148 记录表] [0x1A8 主题数据区] [0x1106 文件区]
```

文件区里每个文件前面跟一个 16 字节头（内容长度，路径长度左移 24 位这类字段），
之后是 4 字节零、路径、文件内容。

记录表从 0x158 起固定 4 条，再加一条尾标记，尾部紧贴 0x1A8 处的主题表。也就是说
**槽数不能增减**：字体移出主包之后，第 4 槽塞了一个几百字节的占位文件
（`installer/font_moved.txt`），让容器结构一个字节都不变。

| 源文件 | 容器内路径 |
|---|---|
| `installer/chaos_installer.lua` | `_lua/chaos-installer/main.lua` |
| `supervisor/chaos_sup.ko` | `_lua/chaos-installer/chaos_sup.ko` |
| `chaos_icon.bin` | `_lua/chaos-installer/chaos_icon.bin` |
| `installer/font_moved.txt` | `_lua/chaos-installer/lxgw.ttf`（占位） |

安装器 11 步，每步占一个 `lv_timer` 拍：

```
1 部署模块 -> 2 部署应用图标 -> 2.5 部署字体 -> 3 加载模块 -> 4 检查设备
-> 4.5 设置语言 -> 5 恢复占位 -> 6 注册应用 -> 6.5 通知系统 -> 7 发布应用
-> 8 发布桌面条目
```

## 字体与图标投递包

字体与图标不在主包里，各自打成一个 `.bin`，与主包同一套容器格式、不同的一组槽。

包的身份证是表盘容器头 `0x28` 处那 12 字节 `pkgName`，**不是** `0x68` 的显示名。
两个包 pkgName 相同，在固件眼里就是同一个包，会互相覆盖。主包的号是固定值；字体包与
图标包的号由内容哈希推导（`4348` 加上内容摘要前 5 字节对 1e8 取模），所以同一份内容
重复打包幂等，不同内容自动分开，多个包可以并存。

设备上的落地位置：

- 图标按包存：`/data/chaos/icons/<包号>/<stem>.bin`
- 字体按槽存：`/data/chaos/font/st<槽号>.ttf`，可投递的槽位是 1 到 8。
  槽 0 是安装器自带那一份，不可投递

两份清单 `/data/chaos/icons/index.txt` 与 `/data/chaos/font/index.txt` 用的是**逐字节
同一套格式**：定长 128 字节，8 行，每行 16 字节，内容是"2 位包号或槽号、一个空格、
12 字节短名、换行"，空槽填 16 个空格。这段读写逻辑在模块和投递脚本里各写了一遍，
刻意没抽公共实现（图标那条链已经在真机上跑通，不想动它），代价是**改格式必须同时改
所有写它的地方**。

另外两条会影响你判断实现是否正确的：

- 设备上**不遍历目录**，清单是唯一来源。目录遍历在真机上死锁过一次，之后一律避开。
- LVGL 的图像缓存按路径常驻。重投同名图标包之后要看新内容，得先切到别的包再切回来。

图标素材规格：画布 112×112，内容外沿不超过 100×100，四边各留至少 6 px 透明。
这几个数字是量固件自带图标得到的。留白那部分是桌面拿去做磁贴间距的，留少了会明显比
系统图标大一圈。像素格式 BGRA8888，加 12 字节头，单个文件 50,188 字节。

## 改代码前要知道的固件事实

下面每一条都对应一次真机上的黑屏重启或静默失效。改这个模块之前先读一遍。

- **固件调用一律走 `src/fw_api.rs`。**业务代码里不该出现裸的 `transmute(0x0C...)`。
- **函数指针地址的 bit0 必须是 1**（Thumb 态）。Cortex-M33 没有 ARM 态，偶数地址一调
  就是 INVSTATE 硬 fault。逆向工具给出的 entry 是偶数（反汇编要用偶数），当指针用
  之前必须自己补上那一位。
- **空串指针不等于 NULL。**副标签传一个只含 `\0` 的缓冲会触发惰性创建，界面上凭空
  多出一行空白。不显示副标签就传封装层里那个 `NONE_PTR`。
- **碰任何 LVGL 对象之前先过存活门 `page_is_live(pid)`。**定时器比页面活得久，缺这道
  门在退出应用时必崩。
- **句柄作废放在 `on_create`，`on_destroy` 不碰状态。**息屏也会走 `on_destroy`，但那时
  对象树还在。在 `on_destroy` 里清句柄会让实时刷新永久停摆。
- **常驻 `lv_timer` 不能用固定频率。**三条规则要一起成立：屏幕门（息屏就不干活）、
  值不变不写（跟上一拍影子比对，变了才写控件）、按忙闲调频（忙 50 ms，息屏且全空闲
  1000 ms）。改周期用 `timer_set_period`，而且**写完必须读回**，对不上就永久退回原
  频率。违反的直接后果是装完后续航雪崩。
- **`lv_timer` 只建一次，句柄建立后永不丢弃。**清句柄不等于释放对象（定时器挂在内部
  链表上），"疑似失效就重建"会让旧实例继续跑并逐轮累积。
- **不要在 UI 线程 read 设备节点。**`/dev` 下字符与块设备的驱动 `read()` 会阻塞到看门狗
  复位：遍历目录时只对 readdir 报 `DT_REG`（普通文件）的条目 open 与 read。目录用
  `opendir` / `readdir` / `closedir`；这里的内核 `open` 不是 POSIX，只读标志是 1
  而不是 0。
- **不要在表盘的 Lua 回调里做需要内核调度锁的操作。**`os.execute` 和 procfs 目录遍历
  必死锁。
- **槽号到回调的映射禁止 catch-all。**`match` 里写 `_ => ...` 会让以后新增的槽位静默
  错配到别的回调上。
- **改容量常量要同步所有清理循环。**少一处就留悬空句柄，后果是 use-after-free。
- **原生应用最多注册 14 页。**真机定案：把 `PAGE_COUNT` 抬到 15、第 15 页借用已有页面
  实现、不含任何新代码，安装到第 4.5 步就黑屏自重启。要加界面只能重新分配已有的
  page_id。机制没查清楚，所以这条按硬上限处理。
- **二级界面必须有独立 page_id。**只有真的 `page_goto` / `page_back` 才有固件的压栈与
  pop 转场动画；页面内部切层级没有动画。
- **页名、注册、页表三处必须同步**：`state.rs` 的页名键、`ipc.rs` 的注册、`page.rs` 的
  `PAGE_TABLE`。
- **固件地址映射**：运行地址 `R` 与镜像文件偏移 `F` 的关系是 `R = F + 0x0C0C0000`。
  字符串常量还要在 0x2C 别名域里搜一遍（偏移再加 `0x20000000`），交叉引用两个域都得扫。

## 怎么验证

这个项目**没有针对固件行为的单元测试**，最终判据是真机上的表现。能离线判定的先离线
判定：

- 构建通过，并且产物里未定义符号为 0。
- 投递链（字体与图标）在离线环境里跑过冒烟：Lua 侧用 mock 把整条逻辑走一遍，目的是
  把"表盘 Lua 有个语法或逻辑错"这类在真机上直接表现为黑屏的问题先钉死。冒烟脚本与
  mock 不在本仓库。
- 上真机之前，判据必须**可分辨**：不同的失败模式要能对应到不同的读数。
- 证据分级，从高到低：真机已验证、真机已探测、静态已确认、静态已还原。
  **编译通过不等于设备可用。**
- 调试读数一律通过二维码或界面显示出来，不写文件 —— 设备上读不了文件。调试用的探针
  完成目的之后，在下一次改动时顺手删掉。

### 字体

霞鹜文楷（LXGW WenKai）按 SIL OFL-1.1 发布，允许自由再分发与改作，条件有两个：随附

### 隐私

模块只在设备本地读 `/proc` 与固件状态，然后把结果显示在手环屏幕上。不联网、不上传、
不采集也不落盘任何用户数据。设备本身有蓝牙，但本模块不用它 —— 蓝牙数据传输那条线
做过探索，最终整体删掉了。

任何你不拥有的设备。

## 术语

| 术语 | 含义 |
|---|---|
| ko | 可重定位 ELF 内核模块，由固件的模块加载器 insmod |
| supervisor | 本项目的常驻模块，持有设备节点 `/dev/chaos` |
| 容器 / 投递包 | magic `0x1234A55A` 的 `.bin`。主包与字体包、图标包同一套壳、不同的一组槽 |
| page_id | 固件在 `on_create` 时传给页面的页号，0 到 13 |
| 页名键 | `page_goto` 解析用的字符串，与界面显示无关 |
| pkgName | 容器头 `0x28` 处 12 字节，固件识别包的身份键 |
| stem | 一枚桌面图标对应的文件名主干，例如 `weather` |
| CIPK | 图标包容器，magic 四个字节 `CIPK`，里面装 N 条 `<stem>.bin` |
| app_id | 注册之后固件分配的应用号，运行时从白名单里取空槽，**不是常数** |

## 贡献

改代码之前先读"改代码前要知道的固件事实"。合并进来的改动要满足：

- 能编过，并且产物里未定义符号为 0。
- 新增页面就同步改页名、注册、页表三处，并且不新增注册页（14 页上限）。
- 固件调用走 `fw_api.rs`，不在业务代码里写裸地址。
- 注释只写基础说明与目标，中文，不用 emoji 和特殊符号；重要性用纯文本前缀标注，
  例如"重要:"、"注意:"、"根因:"。
