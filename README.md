# Chaos

在小米手环 10 Pro 上跑自己写的原生应用。一个 `no_std` 的 Rust 内核模块，配一段 Lua 安装器，
装完之后桌面图标栏里会多出一枚 Chaos，点进去的页面、控件、转场动画跟系统自带的那些一模一样。

不联网，不依赖手机，不碰固件分区。

- 设备：小米手环 10 Pro（p67）
- 固件：3.101.043。地址是这一版逐条核出来的，别的固件别用。
- 语言：Rust 加 Lua，设备侧没有任何第三方依赖
- 许可：AGPL-3.0，全文在 `LICENSE`

## 为什么做这个

手环允许你自己写表盘，走的是一条 Lua 运行时。那条路能画东西，但也就能画东西 —— 想换系统
字体、想换桌面上那些应用图标、想看看 `/proc` 里到底有什么，Lua 层一概够不着。

想再往里一层，只有内核模块这条路。固件本身没给用户装原生应用的入口，可它注册表盘应用的
那条链是敞开的：先落地文件，再 `insmod`，然后告诉固件"这里有个应用，页在这儿"。这个项目
做的就是从那条链进去，把注册出来的应用换成我自己的。

顺带解释一下为什么界面看起来那么"系统"：因为那些页面真的是固件建的。我提供 `on_create`
里放什么行、`event` 里响应哪一格，剩下的排版、字体、按压反馈、页面进出动画全是固件自己的。

## 能干什么

主页顶部三行是实时读数：存储、内存（这两行带进度条）、CPU。读数下面是四个入口 —— 文件
管理、表盘管理、亮度、系统美化。功能整个列一遍：

- 文件管理：逛设备的文件系统，最深四级；文本文件分段读，二进制按 strings 把可打印串抠出来
- 表盘：列内置和市场表盘，点一下就切；再勾一遍哪些参与摇一摇轮换
- 亮度：手动挡加自动挡
- 缓存清理：统计一遍再清
- 更换字体：字体投进设备后列成复选框清单，点一下就换，不用重启；删字体要确认两次
- 桌面图标：桌面 38 个应用位的图标（这版固件里实际存在 35 个）换成你自己的，能一键还原

字体和图标不是塞在主包里的，各自一个 `.bin` 单独投，投完不用重启，模块分批替换。
这两条链的格式完全一样，看"字体和图标怎么投"。

## 快速开始

装工具链：

```bash
rustup toolchain install nightly
rustup component add rust-src --toolchain nightly
rustup target add thumbv8m.main-none-eabi
```

`-Z build-std` 是 stable 给不了的，所以必须 nightly。`rust-lld` nightly 自带。

编静态库：

```bash
cd supervisor
RUSTFLAGS="-C target-cpu=cortex-m33 -C target-feature=-fpregs" \
  cargo +nightly build --release --target thumbv8m.main-none-eabi \
    -Z build-std=core,compiler_builtins

ls target/thumbv8m.main-none-eabi/release/libchaos_sup.a
```

那两个 flag 别省。手环这颗 SoC 没有浮点寄存器，硬浮点编出来的 ELF 属性跟官方产物不一样，
加载器直接不认。要盯的是 `e_flags` 和 `.ARM.attributes` 这两处，跟官方模块对上才算过。

再往后的链接和校验命令写在下一节，包括每条参数为什么必须在。

## 从 `.a` 到能加载的 `.ko`

```bash
rust-lld -flavor gnu -r --gc-sections \
         -u module_main -u chaos_ctor \
         -T merge_sections.ld \
         -o chaos_sup.ko libchaos_sup.a
```

四条参数各自都在救一个坑：

`-r` 出可重定位 ELF。Vela 的模块加载器只吃这种，可执行 ELF 它不接。

`--gc-sections` 控体积。`-Z build-std` 底下每个函数一个段，不 GC 就把 `core` 的整个 `.text`
全拖进来，我这边实测 550 KB 上下，而 `insmod` 的上限是 256 KB。

`-u module_main -u chaos_ctor` 保住两个入口。这俩没有任何调用方，垃圾回收会把它们当没用人掉。

`-T merge_sections.ld` 把 `.text.*` 合成连续一段，顺手丢掉 `.llvmbc`。`rust-lld -r` 不会
自己合，少了这一步 `.text` 大小是 0，而加载器对此一声不吭 —— 模块照样"装成功"，界面上却
什么都不会动，只有去 section header 里读长度才看得见。这个脚本得自己写，要干的事就前面那
两句：归拢 `.text.*`，丢弃 `.llvmbc`。

链完之后所有节的 `sh_addr` 都是 0，得重排成连续布局再交给加载器。不然 `.rodata` 会压在
`.text` 上面，现象是切表盘的时候崩。

最后校验一件事：未定义符号必须是 0。这个模块没有能解析外部符号的阶段，留一个未定义符号
就是运行时跳飞。

## 装到手环

模块、安装器 Lua、应用图标打进一个表盘容器 `.bin`，手环就把它当一枚第三方表盘收下来（跟
你自己装表盘是同一条路）。配对手机端投递过去，在表盘管理里切到它，安装器界面点 Run，11 步
走完桌面上就出现图标。

有一点会让你以为是 bug：第二次点 Run 会在"加载模块"那一步失败，提示你先关机再开机。这是
故意的。固件那张应用注册链表在模块被卸掉之后条目会悬空，launcher 下一轮回巡碰到它就崩，
所以这套流程里从不 `rmmod`，宁可让你重启。

## 它是怎么跑起来的

```
Lua 安装器（在固件的表盘 Lua 运行时里）
   |  把模块和图标写到 /data/chaos
   |  insmod chaos_sup.ko
   v
chaos_sup（常驻内核模块，持有设备节点 /dev/chaos）
   |  从设备文件收命令，去调固件的注册链
   v
注册应用 com.chaos.manager -> launcher 出图标 -> 点图标进页 0
   |
   v
14 个页面的 on_create / on_destroy / event 都在模块里的 PAGE_TABLE
```

安装器每走一步都要让出一个 `lv_timer` 拍，也就是让固件事件循环完整转一圈。这个不是洁癖：
注册链走到一半的时候去读它的状态，读到的东西会把后面几步带坏。

## 十四个页面

14 页是上限，不是我的洁癖。我把 `PAGE_COUNT` 抬到 15、第 15 页借用一个现成页面实现、
里面一行新代码都没有，安装到第 4.5 步就黑屏自重启。机制我没查清，所以先当硬上限用，
要加界面就重新分配已有的 page_id。

页名键是给 `page_goto` 解析用的字符串，跟屏幕上显示什么没关系。标题栏显示的是"你点哪一行
进来的"那一行的文字。

| page_id | 页名键 | 界面 | 干什么 |
|---|---|---|---|
| 0 | `main` | Chaos | 存储、内存、CPU 读数，六个入口 |
| 1-4 | `files` `files1` `files2` `files3` | 文件管理 | 目录 1 到 4 级，条目、更多、返回 |
| 5 | `textsub` | 更换字体 | 复选框清单、切换、两步删除 |
| 6 | `iconsub` | 桌面图标 | 图标包列表、应用、还原 |
| 7 | `viewer` | 文件查看 | 文本分段读，二进制抠可打印串 |
| 8 | `wfaces` | 表盘切换 | 内置加市场表盘，点选即切 |
| 9 | `wfshake` | 摇一摇轮换 | 勾选哪些表盘参与轮换 |
| 10 | `wfmgmt` | 表盘管理 | 摇一摇开关，进 8 和 9 |
| 11 | `bright` | 亮度控制 | 当前亮度，自动亮度开关 |
| 12 | `cache` | 缓存清理 | 统计并清理 |
| 13 | `fontd` | 系统美化菜单 | 更换字体、桌面图标、返回 |

主页槽位是固定的：0 存储、1 内存、2 CPU、3 文件管理、4 表盘管理、5 亮度、6 系统美化。
显示的时候我把 CPU 挪到了最前面，但槽号没动 —— 那两个数字不是一回事，别去对。

## 容器格式

magic 是 `0x1234A55A`。

```
[0x000-0x147 头部与主题表] [0x148 记录表] [0x1A8 主题数据区] [0x1106 文件区]
```

文件区里每个文件前面一个 16 字节头（内容长度、路径长度左移 24 位这类字段），然后 4 字节零、
路径、内容。

记录表从 0x158 起固定 4 条再加尾标记，尾巴就贴在 0x1A8 的主题表上，所以**槽数一个都不能动**。
2026-09-26 我把字体挪出主包的时候，第 4 槽只能塞一个几百字节的占位文件（现在那个
`font_moved.txt`），为的就是容器结构一个字节都不变。

| 源文件 | 容器内路径 |
|---|---|
| `installer/chaos_installer.lua` | `_lua/chaos-installer/main.lua` |
| `supervisor/chaos_sup.ko` | `_lua/chaos-installer/chaos_sup.ko` |
| `chaos_icon.bin` | `_lua/chaos-installer/chaos_icon.bin` |
| `installer/font_moved.txt` | `_lua/chaos-installer/lxgw.ttf`（占位） |

11 步是这么排的，每步一拍：

```
1 部署模块 -> 2 部署应用图标 -> 2.5 部署字体 -> 3 加载模块 -> 4 检查设备
-> 4.5 设置语言 -> 5 恢复占位 -> 6 注册应用 -> 6.5 通知系统 -> 7 发布应用
-> 8 发布桌面条目
```

步号里为什么有 2.5 和 4.5 这种小数：那些位置是后来插进来的，插的时候没重排号，因为界面
上显示的就是这串字符串，重排会让老截图和老记录全部对不上。

## 字体和图标怎么投

字体和图标都不在主包里，各打一个 `.bin`，跟主包同一套容器格式、不同的一组槽。

身份键是容器头 `0x28` 那 12 字节 `pkgName`。注意不是 `0x68` 那个显示名 —— 两个包只要
pkgName 一样，固件就认为它们是同一个包，互相覆盖。我第一次踩这个坑是因为字体包和主包都
继承了模板的 `000000000000`。

包号的做法：主包固定一个号；字体包和图标包的号从内容哈希推出来（`4348` 开头，后面 8 位
是摘要前 5 字节对 1e8 取模）。这样同一份内容重打幂等，不同内容自动分开，多个包能并存。

不过有一个副作用你得知道：哈希算的是**处理之后**的字节。改一次素材预处理，同一个字体会
算出新包号，设备上就变成两个包、多占一个槽。我 2026-09-30 加了垂直度量归一化，之后重打
才发现同一个字体换号了，所以
重投已经在线上的包请显式指定原来的包号，别信自动推导。

设备上的位置：

- 图标按包存：`/data/chaos/icons/<包号>/<stem>.bin`
- 字体按槽存：`/data/chaos/font/st<槽号>.ttf`，能投的槽是 1 到 8。槽 0 留给安装器自带那份

两份清单 `icons/index.txt` 和 `font/index.txt` 是逐字节同一套格式：定长 128 字节，8 行，
每行 16 字节，写法是两位包号或槽号、一个空格、12 字节短名、换行，空槽填 16 个空格。这段
读写在模块里和投递脚本里各写了一份，我故意没抽公共实现 —— 图标那条链已经在真机上跑通了，
不想为了省 40 行去动它。代价很清楚：改格式得同时改所有写它的地方，漏一处就是界面和清单
不一致。

还有两条会误导你判断的：

设备上**从不遍历目录**，清单是唯一来源。procfs 遍历在真机上死锁过，之后一律避开。
LVGL 的图像缓存按路径常驻，重投同名图标包之后要看新内容，得先切到别的包再切回来。

图标素材的规格是量固件自带图标得来的：画布 112×112，内容外沿不超过 100×100，四边各留
6 px 以上透明。留白不是装饰，桌面拿它当磁贴间距用，你留少了那枚图标就会比系统图标大一圈，
一眼看得出来。像素格式 BGRA8888，加 12 字节头，一个文件 50,188 字节。

## 已知限制

只适配 3.101.043。换固件要重做地址表，不是改几个常量的事。

14 页是硬上限，界面向的扩展只能重新分配已有 page_id。

文件管理只能进四级目录，`/data/chaos/icons/01` 这种就进不去了。那两个 id 是让给了美化的
二级页，因为转场动画那条要求更硬。

桌面图标换不到日历那一格。日历磁贴不是 launcher 按注册表图标路径画的，是万年历应用自己
画的：一张白色圆盘底（路径写死在代码里，在只读的 romfs 上）加两枚固件画的文字（星期、
日期数字）。换图机制改的是注册表节点的图标指针，那条字面量不经过它。另外两枚文字是按白底
配的深色，所以就算换底图，深色素材也会让日期读不出来。

换完字体之后，正在前台那一页的标题栏可能还挂着上一代的字形，整条不画，退出重进就好了。
根因是标题栏上的字体是固件直烘的本地属性，样式级写回盖不住它；唯一能改写本地属性的逐对象
补写又被"我们的页在前台"这把门锁死，一拍都不跑。目前是把标题对象在重建时一起删掉重建，
等于把"退出重进"自动化了。

## 我怎么验证

没有针对固件行为的单元测试，这个项目里最终判据是真机上的表现。能离线判的我先离线判：

构建通过，产物未定义符号为 0。投递链在离线环境用 mock 把整条 Lua 逻辑跑一遍（字体 229 项、
图标 53 项），目的是把"表盘 Lua 有个语法或者逻辑错"这类在真机上直接黑屏的问题先钉死 ——
每少猜一次就少刷一次机。

上真机之前判据必须能分辨：不同的失败模式得对应到不同的读数，不然那一趟白跑。

我自己给结论分四档，从高到低：真机已验证、真机探测过、静态确认、静态还原。**编译通过跟
设备可用是两件事**，这份 README 里哪些是前者哪些是后者，我尽量写清楚了。

调试时候的读数一律用二维码或者界面显示出来，不落文件 —— 你在设备上读不了文件。探针用完
下一次改动顺手删掉，不然半年后你会在代码里看到一堆没人知道干什么的分支。

而且下游继续用同一份许可。

想把这套东西接进闭源项目，唯一干净的路是 clean-room：只保留固件地址、结构偏移这类**事实**
（事实不受版权保护），把照抄的逻辑和容器实现全删掉自己重写一份。

## 隐私

模块只在设备本地读 `/proc` 和固件状态，结果直接显示在手环屏幕上。不联网、不上传、不采集、
不落盘任何用户数据。设备是有蓝牙的，但这个模块不用它 —— 蓝牙传数据那条线我探过，最后整条
删了，代码里没有通路。

## 风险

这套代码是走固件的注册链把应用塞进你的手环，属于非授权修改：可能失去保修，可能变砖，可能
下次固件升级就失效。请只在你自己拥有的设备上弄，风险自己担。别刷你不拥有的设备。

## 想改点什么

这个模块跟固件贴得很近，改动容易踩到看不见的地方 —— 源码注释里标了"重要:"、"注意:"、
"根因:"的那几行就是坑的位置，动手前先把要改的那个文件里这几类注释读一遍。合并进来的改动
我要看这四条：

- 能编过，而且产物未定义符号为 0
- 加了页面就同步改页名、注册、页表三处，而且不新增注册页（14 页上限）
- 固件调用走 `fw_api.rs`，业务代码里不出现裸地址
- 注释只写基础说明和目标，中文，不用 emoji 和花哨符号；重要的地方用文本前缀标一下，
  比如"重要:"、"注意:"、"根因:"

## 术语

| 术语 | 含义 |
|---|---|
| ko | 可重定位 ELF 内核模块，固件的模块加载器 insmod 的就是它 |
| supervisor | 本项目的常驻模块，持有设备节点 `/dev/chaos` |
| 容器 / 投递包 | magic `0x1234A55A` 的 `.bin`。主包、字体包、图标包同一套壳不同槽 |
| page_id | 固件在 `on_create` 时传给页面的页号，0 到 13 |
| 页名键 | `page_goto` 解析用的字符串，跟显示无关 |
| pkgName | 容器头 `0x28` 处 12 字节，固件认包的身份键 |
| stem | 一枚桌面图标的文件名主干，比如 `weather` |
| CIPK | 图标包容器，magic 四个字节 `CIPK`，里面装 N 条 `<stem>.bin` |
| app_id | 注册之后固件分配的应用号，运行时从白名单取空槽，不是常数 |
