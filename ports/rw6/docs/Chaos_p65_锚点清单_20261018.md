# Chaos → p65 锚点清单与定位手法（2026-10-18）

这份清单是从代码**现抽**的，不手抄：`Chaos-Module/supervisor/src/fw_api/*.rs` 里所有
`0x0Cxxxxxx` 字面量，按"所在函数/常量名"归到符号上，去重后落成
[`Chaos_p65_锚点清单.csv`](Chaos_p65_锚点清单.csv)。

**数字（现抽）：213 处地址 / 113 个符号 / 8 个模块**。
分布：sys 78、gfx 65、fs 16、page 13、picker 12、event 10、home 10、glass 9。
（`0x0C0C0000` 那种"基址/占位"已剔掉，不算锚点。）

## 状态口径

`p65_status` 现在整列是 **待定位** —— 这是诚实的起点：这些问题目前**没有一个**在新机型上
拿到过"地址 + 签名 + 模拟器里跑通"三件齐的对应。填法只有四档，别混：

| 档 | 含义 | 判据 |
|---|---|---|
| 待定位 | 连候选都没有 | —— |
| 候选 | 结构/字符串/调用形状对上，但没在模拟器里跑过 | 记录候选地址与匹配依据 |
| SIM | p65 的 flint 跑批里该入口被命中过（站点计数 > 0） | 站点地址按 `addr_conv` 现算 |
| DEVICE | 真机可用 | 本项目当前**不可能**到这一档（无真机） |

填一行必须同时写：p65 地址、Ghidra 函数名/入口、站点命中的 run 编号、依据一句话。
只写"很像"的不要填 SIM。

## 各模块的定位手法（p65 与 043 的差异决定了走哪条路）

- **fs（16 处）**：这些是 POSIX 包装（open/read/close/ioctl/lseek/opendir/readdir/closedir）。
  p65 的内核在 PSRAM 执行别名 `0x1C000000` 域，libc 调用腿是 8 字节长跳 veneer
  （表起 file 0x7FE000 一带，`write` = file 0x7FE040 → `0x1C159A2D`）。
  **别按 043 的 XIP 地址平移**：先在 p65 里按"符号同名 + 调用腿"找，再用站点在跑批里验证。
- **gfx（65 处）**：LVGL 一族。p65 的 LVGL 与 043 不同源（代码同源度 8-14%），
  但**行为锚点可复用**：例如 `style_apply` 在 043 的判据是 `0x2010D300` 这一族参数、
  `row_update` 的判据是"文本 + trailing state + 逐字节字体回退检查"。
  做法：先拿行为锚点在 p65 里定位到一个，再顺着调用图扩（`ghidra_fw.py fns` 一次查多地址）。
- **page / sys（91 处）**：页面管理器与注册链。p65 的 `PAGE_MGR` 一族已经有文档线索
  （`page_desc_by_index` 的参数是页栈位置不是页 ID；`obj_align_to` 的 OUT_* 是"放到基准物外侧"），
  这些**语义**可以直接搬，**地址**必须重新定位。
- **picker / event / home / glass（41 处）**：控件与事件总线。滚轮那一套（zoom_picker_*）
  在文档里有逐条调用序列（注册、设范围、设值、刷新、挂事件），p65 上要重走一遍同样的序列取证。

## 为什么现在只到"清单"这一步

移植当前卡在**模拟器还没出第一帧**（`lcdc 帧=0`），而上面 213 个锚点的验证全部依赖
"模拟器能跑到注册链"这一前提。顺序上先打通首帧，锚点定位才有判据可用；
反过来先做锚点映射，只能得到"静态很像"的候选，等级上不去。

所以这份清单的用法是：**首帧一出来，按模块从上往下扫，一行一行填状态**；
每填一行都要附一次模拟器读数，不许只写地址。

## 维护

- 重新生成清单：跑本文件顶部描述的那段抽取（脚本在 `_probe/` 会话内，一次性；需要时重写，
  抽取规则就三句：只认 `0x0Cxxxxxx` 形式的字面量、按最近的 `fn`/`const` 归属、剔掉基址常量）。
- `fw_api` 增删锚点后必须重抽一遍再对比，别让清单与代码漂开。

## 已排除的一条快路：043 与 p65 之间不能拿函数序言字节对拷

想过一条省事的办法：043 的锚点函数已经定位完，如果 p65 的 LVGL 是同一次构建，
直接拿 043 函数入口的 8/16 字节在 p65 镜像里搜，就能把整张清单一次性平移过去。

**这条路不成立**（做过阳性对照，所以这个阴性算数）：

| 取样 | 在 043 自己里出现 | 在 p65 里出现 |
|---|---|---|
| `obj_set_width`（file 0x004C8420）取 8 字节 | 2 次 | **0 次** |
| 同上取 16 字节 | 1 次 | **0 次** |
| `set_text`（file 0x004C9490）取 8 / 16 字节 | 2 / 1 次 | **0 / 0 次** |

对照那行是关键：同一段字节在 043 自己里能搜到（16 字节唯一命中），说明取样与搜索都对；
在 p65 里 0 命中就是真的不共享机器码。两版镜像里 `style` 这个名字都出现上百次（100 / 98），
说明 LVGL 两边都在，但**不是同一次编译的产物**（内联、寄存器分配、顺序都不同）。

⇒ 锚点定位只能按本文件上面写的逐模块打法走（字符串锚 + 结构特征 + 模拟器读数），
不要再去试字节对拷。要提速就按 `ghidra-firmware-analysis` 里那条**批量**问法：
一次 `fns` 问一串地址，不要一个地址起一次 headless。
