# 表驱动控件的动画律：取证与移植

## 适用与判据

命中下面**两条以上**就别再找"那条公式"了，它就是查表的：

- 构造函数里出现多段 `ldm/stm`、`vstr` 成对写入，或反复调一个只有几条指令的小函数；
- 目标对象里出现成片等距的浮点对（斜率, 截距）或成片等长常量；
- 改"某个位置的值"会让曲线局部变形，而不是整体平移。

## 五步取证

1. **找建表函数**（通常是 ctor）。看 `add.w rX, rObj, #off` 与 `stm`/`vstr` 的落点：
   得到表首偏移数组。相邻表首之差 ÷ 每项宽度 = **项数**；项数 ÷ 列数 = **段数**。
   坑：表间距正好等于"项数 × 项宽"时，容易把同一张表的相邻项误读成"两份副本"。
2. **读建线函数**。典型是"给两点 (x0,y0)(x1,y1)，返回 (斜率, 截距)"：
   `slope=(y1-y0)/(x1-x0)`、`intercept=y0-x0*slope`。据此确认表存的是**分段线性**，
   不是某种魔数。
3. **拿作者原值**。从活体实例把表值读出来，同时去镜像里找那段常量数组（一般就在
   字符串池/data 段附近），两边逐位对上才算数 —— **不要拟合**，拟合出来的数会在另一个
   距离上崩掉。N 个锚点会得到 N 段（两端各补一段斜率 0 的平段），别按 N-1 算。
4. **定自变量**。三张表不一定都吃同一个输入：常见是
   `x=lerp(t1,pos)`、`y=lerp(t2,pos)`、`scale=lerp(t3,y)` —— **第三发吃第二发的结果**。
   域数组（如 0/73/146/… 或 0/150/300/…）告诉你输入的单位与档距；两个域数组同时存在，
   说明有两套模式（由某个模式位选）。
5. **移植口径**：按**锚点序号**搬值（"第 k 排取 Q[k]"），不要按屏幕像素搬 ——
   原机的排布可能带鱼眼压缩（排距 44/88/105/…），照像素搬会把曲线一起搬歪。
   布局那一半（鱼眼排距、列外鼓）属于原机排版，只写 scale 的移植拿不到，要明说。

## 陷阱（都实测踩过）

- **名字池零调用点 ≠ 死代码**：可能走函数指针表、或调用方在别的镜像里。
  任何"0 处"结论都要先做阳性对照（拿一个已知被调的函数跑同一个扫描器）。
- **BL 解码别自己写**：`I1=~(J1^S)`、`I2=~(J2^S)`，且 J1/J2 在 h1 的 bit13/bit11。
  写错会得到"这批入口零引用"的假阴性，而结论看上去完全合理。
- **判据不许引用自己写下去的值**：缩放判据读盒宽、盒宽由 scale 决定 —— 滚远一点就掉出判据、
  再也回不来。要么给输出加下限，要么用与写入无关的量做门。
- **屏上一页显示不下读数**：日志块常常二十多行，而日志页一页只显示 8 行；
  在块尾压一行汇总（`in/rows/cols/pit/mid/far/d`），现场只翻第一页就够。
- **判据一个都不认时要能自证**：额外记几个"差一点"的样本（够方、尺寸在放宽区间却没进判据的），
  给出真实宽高/类型/落点，否则调参只能猜。

## 验证三件套（不需要真机也能验到"写对值"）

1. **纯函数自检**：把律抽成不碰内存的纯函数，首拍按几组坐标打四发期望值
   （中心 / 外列 / 中列 / 另一外列），与主机侧独立现算对逐位。
2. **摆网格探针**：拿真实对象临时摆成 N 列 M 排，跑完整条读路径（读 coords→过判据→算律→写），
   **同一拍内还原坐标**；读数应与你预先算的值逐位相同。验完把探针整段删掉。
3. **字段读回**：直接读目标结构的字段（例如 `lv_image_t+0x50/+0x54` = scale_x/scale_y），
   确认落盘值。注意对象树在息屏/唤醒时会重建 —— 要取**最后一批**日志里的地址。
